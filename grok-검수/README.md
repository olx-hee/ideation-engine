# Grok 검수 폴더

Cursor Grok(검수자) 전용 공간. 주 개발(Claude) 코드는 건드리지 않고, 검수 결과만 여기에 쌓는다.

## 구조

```
grok-검수/
├── README.md              ← 이 파일
├── 최신보고서/            ← 지금 기준의 단 하나 (가장 최근 검수)
└── 지난보고서보관/        ← 새 보고서가 생기면 이전 최신을 여기로 이동
```

## 자동 절차 (Grok이 검수 요청마다 실행)

사용자가 “검수해줘 / 리뷰해줘”라고만 해도 Grok이 **묻지 않고** 아래를 한다.
규칙 파일: `.cursor/rules/grok-report-workflow.mdc`

1. `최신보고서/` 안의 기존 `.md`를 `지난보고서보관/`으로 **이동**
2. 검수 수행 (`.cursor/rules/reviewer.mdc` 형식)
3. `최신보고서/`에 새 보고서 작성  
   파일명: `YYYY-MM-DD_HHMM_범위.md`  
   예: `2026-08-02_2030_전체검수-및-워킹트리diff.md`
4. 채팅에는 요약 + 보고서 경로만 안내

## 보고서 범위 표기

| 표기 | 의미 |
|------|------|
| 전체검수 | `src/App.jsx` 등 현재 코드베이스 전수 |
| 워킹트리diff | 아직 커밋되지 않은 변경 |
| HEAD | 최신 커밋만 |
| 보안 / 정직성 / UX | 집중 검수 |

## 역할 경계

- 기본: **리뷰만**. 이 폴더에 보고서 작성.
- 코드 수정: 사용자가 "고쳐줘"라고 명시할 때만, 지적한 항목만 최소 diff.
- 알려진 목업(팀원 입장 가짜, AI 하드코딩 메시지 등)은 새 버그로 치지 않음. 실서비스 위험은 지적 OK.
