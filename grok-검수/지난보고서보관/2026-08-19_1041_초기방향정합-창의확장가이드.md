## 0. 요약 판정

**초기 방향의 큰 줄기(난이도별 라우팅 + 실측·도구 보조)로는 잘 가고 있다.**  
다만 성공 정의가 처음에 상상한 **「특화·품질 우위로 단일 AI를 이긴다」**에서, 데이터에 맞게 **「싸게·맞게·정직하게 라우팅하는 세션 엔진」**으로 옮겨진 상태다. 이 재정의를 받아들이면 구상과 **정합**하고, 특화·품질우위를 다시 전면에 두면 **데이터와 충돌**한다.

창의성을 더하려면 모델 순위가 아니라 **세션 규칙·다성(多聲)·산출물 파이프**에서 키우는 것이 벤치·정직성(§5)과 맞다.

**Blocker 0 / High 0 / Medium 2 / Low 2** (전략 리스크; 코드 High는 종합검수의 미터·reasoning 불일치가 여전히 잔여)

## 1. 초기 방향성 정합 검수

### 1-1. 맞는 축

| 초기 생각 | 현재 상태 | 판정 |
|-----------|-----------|------|
| 단일 만능 프롬프트가 아니라 **제품·구조** | 각도·방식·오프/온·영속화·오케스트레이터 | ✅ |
| **가볍 = 싼 AI** | ice/keyword → Gemini-2.5-Flash-Lite (실측·코드) | ✅ |
| **무겁 = 더 적합한 AI** | analyze 벤치에서 추론형·Solar 상단 경향 (잠정·재검증 전제) | ✅ 방향 / ⚠️ 코드는 아직 GLM+추론OFF |
| **오픈·도구로 보조·측정** | OpenRouter 벤치 하네스, Map-Reduce·Langfuse 검토 | ✅ 방향 |

### 1-2. 약해지거나 바뀐 축

| 초기 생각 | 실측·검수 결론 | 정직한 재정의 |
|-----------|----------------|---------------|
| 특화 AI에 맞추면 **성능↑** | 각도 특화 재현 실패(노이즈) | **특화 최적화 금지** → 다양성 분산 + 난이도 티어 |
| 분업이면 단일보다 **아이디어 품질↑** | A/B·통제: 우위 불성립, 나누기만 하면 손해 가능 | **대등~근소 열위 × 훨씬 싼 비용** + 작업별 적합 모델 |
| “의미” = 더 창의적 출력 | 벤치 overall로는 증명 어려움 | “의미” = **세션 진행·라우팅 정직·비용·다성** |

### 1-3. 잔여 기술 갭 (방향 이야기와 별개로 뚫린 구멍)

종합검수와 동일 — 방향성 스토리를 말할 때 같이 고칠 것:

1. 미터 `estimate-mock` (절감 슬라이드 정직성)  
2. flagship **벤치=추론 ON** vs **코드=추론 OFF**  
3. ANGLE `Solar-Pro-3` / 「특화」주석 vs 「특화 노이즈」프레임  

**Medium:** 위 갭을 둔 채 「실측대로 난이도 라우팅 중」이라고 발표하면 과장.

## 2. 창의 확장 — 어떻게 진행할 것인가

전제: **특화·품질 점수로 창의성을 포장하지 않는다.**  
창의성은 **세션·상호작용·산출물 형태**에서 키운다 (데이터·§5와 충돌 없음).

### 2-1. 제품 창의 (레버리지 최상)

이미 있는 각도·SCAMPER·6모자·오프/온을 “화면만 다른 브레인스토밍”이 아니라 **강제 규칙**으로 깊게:

| 아이디어 | 요지 |
|----------|------|
| **교차 리믹스** | 각도 A 산출을 B가 **비틀기만** (확장·반박·결합 중 하나 지정) |
| **제약 카드** | 라운드마다 금지어·예산·시간·금기 기술 |
| **역할 턴** | 투표 전 악마의 변호사 / 옹호자 1턴 (모델 또는 사람) |

→ 심사·사용자에게 “창의적 **진행**”으로 읽힘. LLM 특화 주장 불필요.

### 2-2. 멀티 LLM = 다성(polyphony), 점수 경쟁 아님

벤치가 지지하는 것: **어휘 다양성**, **난이도 라우팅**.  
창의 스토리로 쓸 때:

- UI에 모델 페르소나 표시 — 문구는 「특화 입증」이 아니라 **여러 목소리**  
- Map-Reduce 종합을 단순 요약이 아니라 **충돌·결합·이상한 하이브리드 1개 강제**  
- 저가 발산 후 **고가 1콜 비평/확장**만 얹기 (“더 좋다” 주장 없이 한 겹)

**금지:** 모델만 늘려 “더 창의적”이라고 하기 (통제실험: 구조만 나누면 손해).

### 2-3. 오픈소스·도구 — 측정 + 창작 파이프

| 층 | 용도 | 예시 |
|----|------|------|
| **측정·정직** | 토큰·비용·A/B | Langfuse(조건부), 벤치 하네스, meter 실측화 |
| **창작 보조** | 산출물·보강 | 세션→덱/원페이지 익스포트, (선택) 조사 1장, 오프라인 음성·화이트보드→카드 |

초기 「깃허브 오픈소스로 보조·측정」과 정합. 라우팅 철학과도 겹침.

### 2-4. 권장 로드맵 (창의 쐐기)

| 단계 | 내용 |
|------|------|
| **지금 (기반)** | 난이도 라우팅 정합(미터 실측, flagship·reasoning 정렬), 특화 주장 제거 |
| **창의 쐐기** | 교차 리믹스 + 제약 라운드 + 다성 UI + (선택) 산출물 익스포트 |
| **다음** | Map-Reduce를 “병합”이 아니라 “이상한 결합 1개”로 소규모 A/B |

## 3. 발표·문서에 쓸 정직한 한 줄

**쓰도 됨:**  
「우리는 만능 프롬프트 하나가 아니라, **가벼운 일은 저가·무거운 일은 맞는 모델**에 맡기고, 세션 규칙으로 아이디어를 구조화하며, 실측으로 비용을 드러낸다. 창의는 **진행 방식과 다성·리믹스**에서 만든다.」

**쓰면 안 됨:**  
「분업이라 품질이 더 좋다 / 각도별 특화 모델을 입증했다 / 모델이 많아서 더 창의적이다.»

## 4. 보안·정직성 (방향 확장 시)

- 창의 기능(리믹스·종합·익스포트·Langfuse)은 **호출 수·원문 분기**를 늘림 → B1·쿼터·§8 고지와 같이 설계.  
- 측정 도구 도입이 **미터 UI의 `measured` 배지를 자동으로 만들지는 않음** — meter SoT는 앱 서버.

---

## 5. 한 줄 결론

**초기 방향(난이도 라우팅 + 도구로 측정·보조)은 맞고, “의미”의 정의만 품질·특화 승리에서 세션·비용·정직 라우팅으로 고치면 된다. 더 창의적으로 가려면 교차 리믹스·제약 라운드·다성 UI·산출물 파이프를 쐐기로 두고, 특화·품질우위 서사는 접어라.**
