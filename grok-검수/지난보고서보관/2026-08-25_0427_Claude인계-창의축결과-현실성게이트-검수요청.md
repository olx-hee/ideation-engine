## 1. 창의 사람축 — 블라인드 A/B 결과
- 방식: 6목표, 각 목표에 **단일(S: Solar 4개) vs 다중(M: 4모델 각1개)** 세트를 라벨 없이 좌/우 무작위(3:3 균형) → 사용자 직감 택1.
- 결과: **단일(S) 4 : 다중(M) 2** (사용자 선호). 예전 n=1의 M 4:2와 **뒤집힘.**
- **판정: "다중 LLM이 사람 눈에도 더 창의적"은 성립 안 함(노이즈).** 창의축도 다중 우위 없음 확정 → 발산 기본=단일 유지 근거 강화.

## 2. 문제 발견 — 결과가 "애매"했던 이유 (사용자 지적)
사용자: *"아이디어가 구현 가능한 수준인가, 쓸모 있는가, 현실성 없지 않나. 현존 안 하는 서비스를 원한다니까 그런 게 나오는데, 왜 현존 안 하는지(수익성/불가능/과거 실패)를 파악하고 주는가?"*

**원인 진단:** 현재 idea 생성 프롬프트 =
> "[사업성][사용자경험][기술][**참신함**] 4관점에서 겹치지 않는 **새 아이디어**"

- 실현가능성·쓸모·"왜 아직 없나" 검토가 **전혀 없음.**
- 오히려 `[참신함]` + "현존하지 않는" 요구가 **공상을 유도** → 실제 산출된 것들: *VR 가상 식탁 · 블록체인 팀기여도 · AI 꿈해몽 운세 · 미출석 시 죽는 가상 반려동물* = 신박하나 **비현실/이미 실패**한 것들. 이게 "애매함"의 정체.

## 3. 수정 — '현실성 게이트' 프롬프트
아이디어마다 아래를 강제 (뻔함·공상 **둘 다** 배제):
```
① 아이디어(구체적, 유행어 남발 금지)
② 실현가능성(상/중/하 + 이유)
③ 왜 아직 세상에 거의 없나 (수익성 / 기술한계 / 규제 / 과거 실패 중 핵심 하나)
④ 넘는 법 (그 장벽을 실제로 어떻게 넘나)
⑤ 진짜 수요 (누가 왜 — "있으면 좋다"가 아니라 실제 겪는 불편)
```

**Before → After 예 (헬스장):**
- Before: "미출석 시 가상 반려동물이 죽는 게임" (공상)
- After: "미참여 시 자동 기부 연동 · 실현가능성 상 · **왜 없나=헬스장은 회원이 안 와야 이득이라 동기 없음** · 넘는 법=헬스장 CSR 마케팅으로 유인 · 수요=돈 아까움을 선한 목적으로 전환"

→ 검증(2목표): 전부 현실적·구체적, 스스로 *"블록체인 아닌 단순 중개로 법적 리스크↓"* 식으로 공상 배제.

## 4. 로드맵 정합
이 수정은 예전 Grok 검수의 **P0("시중검색·신선도 게이트 + 잠복니즈 판정")**와 같은 지점. 사용자가 결과를 보고 **독립적으로 같은 결론**에 도달함. "현존 안 함"만 좇던 것 → **"이미 있나? 없으면 왜? 넘을 수 있나? 실수요 있나?"**를 통과한 것만.

## 5. Grok에게 (검수 질문)
1. **원인 진단**([참신함]+"현존X" 요구가 공상 유도)이 맞나? 더 근본 원인은?
2. **수정 방향(현실성 게이트 ①~⑤)**이 타당한가? **과교정 위험**(너무 보수적 → 뻔한 아이디어만, 잠복니즈의 '아직 없음' 죽이기)은 어떻게 막나?
3. ③"왜 아직 없나"·⑤"진짜 수요"를 **LLM 추정에만 맡기면 환각 위험**(그럴듯한 거짓 이유). **시중검색 실측**이 반드시 붙어야 하나, 아니면 LLM 추정 + 라벨(추정임 표시)로 충분한가?
4. 이걸 **idea 기본 프롬프트로 박아도** 되나, 아니면 **발산은 자유롭게 두고 별도 '현실성 검토 패스'**(생성→게이트)로 분리가 맞나?

## 6. 정직성 셀프체크
- 창의축 n=6·평가자 본인 1명·pro 편향 가능. "단일 4:2"도 표본 작음(방향 신호).
- 현실성 게이트 프롬프트 검증은 **2목표뿐**, LLM 자기 판정(사람/검색 실측 아님).
- ③⑤는 아직 **LLM 추정**(시중검색 미연동) → 환각 가능, 실측 전 "추정" 라벨 필요.
- 아직 **코드 미반영**(프롬프트 실험 단계).
