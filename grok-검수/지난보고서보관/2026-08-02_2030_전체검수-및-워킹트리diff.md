## 2. 발견 목록 (심각도순)

### [High] `src/App.jsx:372` — 아이스브레이킹이 사용자가 정한 세션 목표를 무시함

· **문제:** `IcePhase`가 세션 `goal` prop을 받지 않고 상수 `GOAL`을 잘라 보여준다. Create에서 무슨 목표를 넣어도 Phase 1 카피는 항상 데모 문장이다.  
· **재현:** 프로필 작성 → 목표를 `"냉장고 관리 앱"`으로 설정 → 세션 진입 → Phase 1 상단에 `"교내 해커톤에서 발표할…"` 계열이 그대로 보임.  
· **제안:** `SessionView`에서 `goal`을 `IcePhase`로 넘기고, UI 문자열은 `goal`만 사용. 상수 `GOAL`은 시드 데이터용으로만 두거나 제거.

### [High] `src/App.jsx:617`, `58`, `265`, `690`, `623` — 근거 없는 수치를 AI·설문 결과처럼 표시

· **문제:** 검수 규칙상 과거 “적합도 %”와 같은 유형. 목업 콘텐츠 자체는 허용이지만, **측정·AI 신뢰도로 읽히는 숫자**가 데모 표기 없이 사실처럼 노출된다.  
  - 분석 신뢰도 `94.2%` (617)  
  - 보고서 `Score: 94/100` (58, 650)  
  - 테마 `pct`·`votes` 고정값 (38–41, 623)  
  - `설문 62명 중 40.3%` (265), `54.8%` (690), 리스크 `33.9%`/`40.3%` (61)  
· **재현:** 아무 세션이나 Phase 3·4 진입. 사용자 입력과 무관하게 동일 수치 표시.  
· **제안:** (1) `AI · 데모` 배지를 Create 주제 추천처럼 붙이거나 (2) 수치 UI 제거·“시연용 샘플” 문구로 교체. 실서비스 전엔 투표/세션 데이터에서만 파생된 숫자만 표시.

### [High] `src/App.jsx:602-635` ↔ `639-695` — 투표 결과가 최종 보고서에 반영되지 않음

· **문제:** Phase 3 투표는 로컬 state뿐이고 Phase 4는 항상 고정 `REPORT`(테마1 우승 내러티브). 돈 낸 사용자 기준으로는 “투표가 먹히지 않는 제품”이다. (보고서 목업은 가이드에 있으나, **투표 UI와 인과가 끊긴 채 1위처럼 말하는 것**은 실서비스 위험.)  
· **재현:** Phase 3에서 Theme 2·3만 투표 → Phase 4로 이동 → 여전히 “AI 커뮤니케이션…” 선정·38%·94점 스토리.  
· **제안:** 목업 유지 시 “시연용 고정 보고서” 명시. 아니면 투표 최다를 `ReportPhase` props로 넘겨 제목만이라도 연동.
