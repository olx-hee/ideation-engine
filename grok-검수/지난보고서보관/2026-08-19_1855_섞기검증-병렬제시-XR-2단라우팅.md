## 0. 요약 판정

사용자 지적(「Solar 편중 vs 초기 섞기 비전」)은 **정당**. 이번 실험은 「문헌식 좋은 섞기」(교차정제·관점선택)를 SR/단일과 맞붙인 **필요한 검증**.

- **자동 최종품질:** SR > SEL > XR ≫ S. 섞기는 SR을 **평균으로 못 넘고 ~40×(vs SR) 비쌈** → **기본 파이프라인 = Solar(+Self-Refine) 유지**에 동의.
- **골별:** XR·SEL이 단독1위 각 2골 — **무의미도 승리도 아님**. 「골마다 다른 승자 = 다양성 신호」.
- **화해 설계(병렬 제시→사람 선택)** 는 품질 클레임과 분리되면 **정직하고 초기비전과 정합**. 자동 synth와 **반드시 구분**.
- XR은 **기본/정밀모드 파이프라인에 넣지 말 것**. 병렬제시에 **후보로 흡수**하거나 후순위 옵션.
- **2단 라우팅 유지 + 선택적 병렬제시**로 충분. 역할/도메인 라우터 추가는 지금은 **과투자**.

**Blocker 0 / High 0 / Medium 3 / Low 2**

> 이를 「섞기 무의미」로도 「섞기 품질 승리」로도 쓰지 말고, **「자동 합산 품질로는 SR, 후보 다양성으로는 섞기 신호」**로 쓴다.

천장(약 3.4~4.4)·n=7·AI심판·심판2 → **잠정**, 방향 뒤집힐 수준은 아님.

## 2. [요청②] 사각지대 — 정직한 한계 vs 변명

| 구분 | 판정 |
|------|------|
| 「LLM-judge 단일 최종점수가 사람 선택의 다양성·의외성 가치를 못 잰다」 | **정직한 한계 인정** — 측정 대상이 다름 |
| 「그래서 섞기가 품질에서도 이긴 셈」 | **변명** — 금지. 평균·비용에서는 **졌음** |

요청서 문헌 요약(RouteLLM·MoA·Blender·BoN·multi-agent fail·multi-LLM collaboration)과 정합: 창의/비정답 과제에서 이득은 **병렬 후보 + 인간(또는 강한 selector)** 쪽에 가깝고, **약한 평균/강제 종합**은 희석(우리 confound·hetero-MoA와 동일 병).

**쓸 문장:** “벤치가 틀린 게 아니라 **우리가 잰 축(자동 최종 품질)과 살리고 싶은 축(팀 선택의 다양성)이 다르다.** 전자에선 SR, 후자는 아직 미측정·제품 UX로 검증.”

## 3. [요청③] 병렬제시 UX 채택

| 기준 | 판정 |
|------|------|
| (a) 초기 「역할·모델 섞기」비전 | **정합** — 자동 평균이 아니라 **모델별 후보를 보여 팀이 고름** |
| (b) 품질 클레임 분리 | **필수.** 「여러 모델이라 더 좋은 점수」금지. 「비교·의외성·부분융합」만 |
| 자동 synth와 구분 | **명확히 구분됨.** 병렬제시 = **합치지 않음**(또는 사람이 고른 뒤만 편집). 옛 ANGLE+SYNTH·SEL의 “자동 선택 후 1묶음”과 다름 |
| §9 과설계 | **옵션·기본 off**면 OK. 기본 경로에 3모델 상시 호출하면 비용·지연 과설계. 카드 2~3·모델 라벨 정직·선택/북마크만 MVP |

**채택 찬성.** 기존 `ANGLE_MODELS` “창의 다성”과 **합치되, SYNTH 자동종합은 켜지 말 것.** 병렬제시 = 다성의 **정직한 구현**.

제품 목표1(단일 프롬프트보다 의미): 사람-in-the-loop 비교가 그 축.

## 4. [요청④] 교차정제(XR)

| 옵션 | 판정 |
|------|------|
| 폐기(연구 종료) | 과도 — 2골 단독승·문헌(교차비평) 신호 있음 |
| 고비용 정밀모드(자동 파이프) | **비추** — SR보다 평균↓·42×↑. §9·정직성 약함 |
| **병렬제시에 흡수** | **권고.** Solar 초안 / (옵션) Kimi 비평·다른 모델 초안을 **나란히** — 자동 Solar 재작성을 강제하지 않음 |
| 나중 “외부비평 1회” 토글 | 병렬 UX 이후에만. 기본 off |

문헌 “교차비평 > 자기비평”은 **조건적**. 이번 실측에서는 **자기정제(SR)가 평균 승** — 비평모델·과제·언어 의존. XR을 기본으로 올리지 말 것.

## 5. [요청⑤] 라우팅 2단 유지?

**충분하다(자동 경로).** 이번 결과는 「Light/Strong + (선택)병렬제시」를 지지하지, 역할/도메인 라우터 R&D를 **지금** 더 파야 한다는 근거는 약하다.

- 문헌 RouteLLM류는 **라우터 정확할 때** 비용↓ — 우리는 KR 아이디어 kind에 맞는 도메인 특화 모델 표가 **아직 없음**.
- 역할 섞기 비전은 **병렬제시 UX**로 더 값싸게·정직하게 충족.
- 도메인 라우팅은: 병렬제시 후 **사람 선호 패턴**이 쌓이거나, 특정 kind에서 Solar가 반복 실패할 때 재개.
