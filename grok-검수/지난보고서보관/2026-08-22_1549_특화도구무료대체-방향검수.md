## 1. 타당성·함정 — Marp+pptx / 검색그라운딩 / Mermaid

### 부합하는 점
- **비용·정직성:** Gamma/Perplexity를 “우리 멀티 LLM”처럼 읽히게 쓰는 함정(CLAUDE.md·MODEL-ROSTER)을 피하고, **렌더=OSS / 조사=이미 쓰는 LLM+검색**으로 가면 “저렴하지만 좋다”·원가 스토리와 맞음.
- **역할 분리:** 내용 생성(LLM) ≠ 슬라이드 디자인(SaaS) — 방법론적으로 옳음. Gamma는 완제품이지 라우팅이 아님.
- **Mermaid:** 분석·로드맵을 텍스트로 남기고 프론트 렌더 — 서버비 $0, 피치 패킷과 잘 맞음.

### 함정 (감수 가치 포함)
| 함정 | 심각도 | 감수?
|------|--------|--------|
| python-pptx/Marp ≠ Gamma 자동 디자인 | 품질 | **감수 가치 있음** — 공모전/해커톤은 “예쁜 SaaS 덱”보다 **근거·시드·이견이 있는 1페이저/구조화 덱**. 템플릿 1~2개면 충분. “Gamma급 디자인” 주장만 하지 말 것 |
| 검색 그라운딩·Brave+LLM ≠ Perplexity 인용 UX | 방법 | 출처 URL·스니펫을 **우리 스키마에 저장**해야 C축(시중검색)이 됨. 그라운딩만 믿고 “사실”로 쓰면 환각·낡은 결과 위험(2334: LLM 기억으로 신규 판정 금지와 동일) |
| Brave/검색 API도 **완전 무료 아님** | 비용 | “$0”은 렌더(Marp/Mermaid)에만 해당. 조사는 **초저가**로 말하는 게 정직 |
| 검색 결과를 프롬프트에 넣을 때 인젝션·SSRF | 보안 | 2228/Claude 자문이 이미 지적 — allowlist·구획·길이 상한 없으면 Medium |
| Marp와 python-pptx **둘 다** 기본 | 과설계 | 하나면 됨. **Marp( MD→덱 ) 우선**, pptx는 템플릿 고정 시 보조 |

**판정:** 조합은 “저렴하지만 좋다”에 **부합**. 단 **품질 동급 주장 금지**, 조사는 **근거 저장 파이프**가 본체이고 도구 이름은 부차.

## 3. 2228 우선순위 — 상충 vs 정합

2228 P0: 병렬후보·이견·사람시드·**시중검색**·데모·원가.

| 항목 | vs 2228 |
|------|---------|
| **자료조사 = 시중검색/신선도 게이트** | **정합.** C축을 제품화하는 것. `research` kind는 P0 근처에서 **시중 배지·유사사례 링크** 범위로 좁혀 구현할 가치 큼 |
| **슬라이드(Marp/pptx)** | **부분 정합·후순위.** 2228의 “피치 패킷/내보내기”와 맞지만, **병렬·시드·시중 UI보다 먼저 하면 산만**. P0 실체 다음에 “내보내기 1종” |
| **Mermaid** | **후순위 보조.** analyze 시각화 — 없어도 데모 성립. 있으면 좋음, P0 아님 |
| **Gamma/Perplexity를 README에 계속 전면** | **상충** — 유료 SaaS 확장으로 읽힘 |

**한 줄:** 자료조사만 2228과 **겹쳐 정합**. 슬라이드+다이어그램을 같은 스프린트에 “특화 스택 3종”으로 올리면 **상충(산만)**.

## 4. 확정 vs 옵션·미구현

| 대상 | 표기 |
|------|------|
| Gamma / Perplexity | **옵션·비권장 기본 / 유료 확장** — “확정 연동” 금지 |
| 검색그라운딩·Brave+LLM (`research`) | **방향 채택**, 코드 전엔 **「채택 방향·미구현」**. 확정 슬러그·단가 숫자는 실측 전 금지 |
| Marp / Mermaid / python-pptx | **내보내기·시각화 후보·미구현** — role map 필수 kind로 넣지 말 것 |
| README | “우리 기본 스택이 Marp다” **확정 금지**. “유료 Gamma 대신 OSS 렌더·검색그라운딩을 **검토/방향**” 수준 |

**이유:** 미구현을 확정으로 박으면 정직성(§5)·심사 질문(“그거 되나요?”)에 바로 깨짐.
