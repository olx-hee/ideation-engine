## 0. 요약 판정

1. **방향(§3): 승인.** 단순/짧은 작업(ice·keyword 등)에 추론(reasoning) 모델을 쓰지 않는 것은 비용절감 철학·설계 A(정적 티어)·정직성과 **정합**한다. registry **라벨도 슬러그에 맞게 바꿔야** 한다(§5 라벨=실체).
2. **모델 조사:** Claude 추천표는 대체로 유효. ice용 1순위는 **비추론 instruct** — 한국어·가성비·창의성 스토리를 나눠 추천한다(아래 §2). 현재 `nvidia/nemotron-nano-9b-v2(:free)`는 **기본 reasoning ON**이라 ice 배정 부적합(실측 out 413과 일치).
3. **보안:** 키 서버 전용·delimiter·목업 폴백은 방향이 맞다. 실호출 이후 **High 1건** — 멱등 가드가 미터만 막고 **`callModel`은 재호출**해 크레딧/무료한도를 태운다. `:free` 로깅·`max_tokens:1024`·에러 본문 로그·B1 부재도 Medium+.

**Blocker 0 / High 1 / Medium 6 / Low 4 / Question 1**

## 1. [요청①] 방향 검수 — 「단순작업 = 비추론 저가」+ P2 ⓐ 구현

### 1-1. 방향 판정: **타당 · 채택 권고**

| 근거 | 설명 |
|------|------|
| 비용 철학 | small 티어 의미는 「짧은 생성·싼 $/답」. reasoning trace가 completion에 잡히면 **티어 라벨이 거짓말**이 됨 |
| 설계 A | ice는 캐스케이드 금지·저가 고정(§4). 추론 모델은 사실상 「숨은 mid/flagship 비용」 |
| 실측 | 핸드오프 로그: ice 한 줄에 out **413**(think 위주). 비추론이면 ~수십 토큰이 정상 |
| Nemotron 자체 | 문서상 unified reasoning/non-reasoning, **기본 think ON**, `/no_think`로 끌 수 있음. 끌어도 「Nemotron=가벼운 small」스토리보다 **순수 instruct로 갈아타는 편이 정직** |

**라벨 ↔ 슬러그:** §5·발표 패널은 `model` 라벨을 보여 준다. `Nemotron-Nano`를 유지한 채 슬러그만 Qwen/Gemini로 바꾸면 **정직성 위반**.  
→ registry `ice`·`ANGLE_MODELS.tech` 라벨을 **실제 쓰는 모델명으로 동시 변경**할 것. 창의성용 Nemotron은 **별 kind/쇼케이스**(또는 mid·에이전트 각도)로 남기는 편이 낫다.

### 1-2. P2 ⓐ `adapter.js` — 설계 정합

| 항목 | 구현 | 판정 |
|------|------|------|
| `callModel` 한곳만 실호출 | OpenRouter fetch + 목업 폴백 | ✅ §6/§9 P2 |
| env 게이트 | `OPENROUTER_API_KEY` + 슬러그 매핑 | ✅ |
| 목업 폴백 | 키 없음/미매핑/실패 → mock | ✅ best-effort |
| 프롬프트 격리 | system + `<<<GOAL>>>…<<<END>>>` | ✅ §8 방향 (강화 여지 §3) |
| usage 실측 필드 | `usageTokensIn/Out` 반환 | ✅ 어댑터 |
| 범위 ⓐ | Nemotron-Nano만 슬러그 | ✅ 슬라이스 의도 |
| capability 자리 | `MODEL_CAPS` 스텁 | ✅ Low로 충분 |
| 목업 usage 결정성 | `stableOut` 해시 | ✅ 재현성(이전 검수 반영) |

### 1-3. 정직성 잔여 (방향과 함께 고칠 것)

| 이슈 | 심각도 | 내용 |
|------|--------|------|
| `PRICING_MODE` 여전히 `estimate-mock` | **Medium** | 실호출·실 usage인데 화면은 「추정」. P2 ⓐ라도 **실호출 콜이 하나라도 있으면** `measured` 또는 콜 단위 `mock` 배지 혼합 필요 |
| 미터가 in/out 미전달 | **Medium** | adapter는 in/out 주는데 `orchestrate` record는 `usageTokens`만 넘김 → §5 usage 분리 미완성 |
| 주석 슬러그 예시 | **Low** | `Qwen3-Flash`→`qwen3-30b-a3b` 등 예시는 thinking 계열일 수 있음. 확장 시 **instruct/non-thinking** 슬러그만 쓸 것 |
| `:free` = $0 사업계획 | **Low** (설계 기지적) | 데모 OK, 상용 $/세션에 영구 $0 금지(§5) |

**방향 결론:** §3 채택. ice에서 Nemotron-Nano(기본 reasoning) **제거·교체** + 라벨 동기화. `/no_think`만으로 버티는 것은 **차선**(스토리·기본값 위험).

## 2. [요청②] 독립 조사 — 가벼운 작업용 저가·비추론 모델 (OpenRouter)

조사 기준(2026-08): **비추론(instruct / thinking 기본 OFF)** · **짧은 생성·키워드·분류** · **한국어** · OpenRouter 슬러그 확인.  
가격·`:free` 목록은 변동 — 배포 직전 모델 페이지 재확인.

| 순위 | 용도 | OpenRouter 슬러그 | 성격 | 한국어 | 비고 |

## 3. [요청③] 실호출 보안·견고성

### 3-1. 잘 된 것

- API 키: `process.env.OPENROUTER_API_KEY`만 — 프론트/`VITE_` 경로 없음(구조상 OK).
- kind 화이트리스트·goal/context 길이 제한 유지.
- 실패 시 목업 폴백(사용자에게 스택 비노출 — 응답은 mock).
- 세션 Map: 이전 High(조회 시 생성)는 **완화됨** — `sessionMeter` 읽기 전용, `MAX_SESSIONS=200`, kind 멱등 플래그.
- GET `/ai-meter`에 `aiLimiter` 적용(이전 대비 개선).

### 3-2. 신규·잔여 이슈

| ID | 심각도 | 이슈 | 권고 |
|----|--------|------|------|
| S1 | **High** | `orchestrate`가 `already`(멱등)여도 **`callModel`을 다시 호출** | `if (already) return` 조기 반환하거나, 실호출 전에 `kinds.has` 가드. StrictMode·재전송 시 **크레딧/:free 한도 이중 소모** |
| S2 | **Medium** | `:free` 사용 시 OR이 **프롬프트·출력 로깅** 가능(모델 페이지 고지) | 해커톤/학교: 유료·no-log 호스트 또는 고지 문구. 아이디어 원문 = 민감 |
| S3 | **Medium** | `max_tokens: 1024` 고정 — ice에 과대 | kind별 상한(예: ice 64~128, report 512+) |
| S4 | **Medium** | `console.warn`에 OR 상태·본문 **200자** | 프로덕션 로그에 사용자 goal 조각·공급사 에러 유출 가능. 코드만/요청id로 축소 |
| S5 | **Medium** | 프롬프트 주입: delimiter는 있으나 goal 안 `<<<END>>>` 탈출·지시 덮어쓰기 미처리 | goal에서 구분자 문자열 strip; system에 「구분자 밖 지시 무시」 |
| S6 | **Medium** | 무인증 `/api/ai` + 실키 = **비용 공격** (B1·일일 쿼터 여전) | P2 실키 공개 전: 리밋 하향, 세션 존재 검증, 일일 쿼터 |
| S7 | **Low** | `fetch` 타임아웃/Abort 없음 | `AbortSignal.timeout(15_000)` 등 |
| S8 | **Low** | 모델 출력 신뢰: API JSON에 `text` 포함. UI는 아직 시연 템플릿 위주이나 연결 시 `<think>`·XSS | 표시 전 think 스트립; React 텍스트 유지(dangerouslySetInnerHTML 금지) |
| S9 | **Low** | `HTTP-Referer: localhost` 하드코드 | 환경별 앱 URL |

### 3-3. 응답 경로 (현재)

- `/api/ai` 응답에 모델 `text`가 포함됨.
- ReportPhase 등은 **미터 위주**; 오케스트레이터 문구를 카드에 바로 넣지는 않는 상태로 보임 → XSS 当面 낮음.
- 연결 시 S8 적용.

## 4. P2 바로 다음 액션 (개발 핸드오프용)

1. ice(+tech) **비추론 슬러그로 교체** + registry 라벨 동기화 (Qwen2.5-7B 또는 Gemini Flash Lite 권장).  
2. **S1 멱등=실호출 스킵** 수정 (비용 High).  
3. kind별 `max_tokens` · delimiter 강화.  
4. 실호출 비율에 맞춰 `pricingMode`/`mock` 배지 정직화 + meter에 in/out 전달.  
5. Solar 라벨을 `solar-pro-3`/`solar-pro4`로 현행화(ux).  
6. `:free`는 로컬 검증만, 발표·공유 세션은 유료·정책 확인 호스트.

## 6. 한 줄 결론

**「단순작업=비추론 저가」는 맞고, ice의 Nemotron-Nano(기본 reasoning)는 교체해야 한다. 후보는 Qwen2.5-7B-Instruct·Gemini Flash Lite·(한국어) Solar Pro 3/4. 실호출 보안의 급소는 멱등 가드가 미터만 막고 API는 두 번 치는 것이다.**
