## 1. 원래 발상 (초기 문제 정의)
> **"대학생들은 회의 진행 능력이 부족한 상태에서 회의·팀플을 진행하며, 이 과정에서 가장 큰 초기 병목인 '팀플 첫 대면'에서 비효율이 발생한다."**

이게 프로젝트의 출발점. 이번 검수는 **지금 만든 것이 이 문제를 실제로 푸는가**를 본다.

## 2. 현재 프로젝트 (확정 상태)
**대상:** 대학생 해커톤·공모전 팀 · 오프라인 첫 회의 · 계정 없음(링크/방 코드 입장).

**흐름(15화면):** 랜딩 → 코드입장 → **프로필(역할+세부 스킬 강점/약점)** → 세션만들기 → 대기실 → **팀 스킬맵** → 아이스브레이킹 → 초반 발산 → **막힘 뚫기 제안(진행자 수락)** → 뚫기 발산(🌱출발점/🔀비틀기/🔁돌아가며) → **현실성 게이트(+Brave 시중검색)** → 분석·투표 → 보고서(+비용) → 세션 완료.

**AI/LLM 사용:**
- 작업별 모델 라우팅(오케스트레이터): 키워드=Flash-Lite / 발산·분석=Solar / 보고·현실성=DeepSeek / 검증=Llama / 검색=Brave.
- 막힘 감지 → 개입 매핑(유사도·발언분포·아이디어수 → 비틀기/출발점/돌아가며). 퍼실리테이션 실무(브레인라이팅·라운드로빈·SCAMPER) 근거.
- 현실성 게이트: 아이디어별 실현성·판정 + **"이미 있나"는 LLM이 아니라 실제 검색(Brave)**이 판정.
- 비용 Langfuse 실측, 품질 promptfoo(동급). **"성능 우위"는 미검증.**

## 3. Claude 자체 진단 (초기 문제 만족도)
**잘 만족하는 부분**
- 회의 진행 능력 부족 → AI가 단계·타이머·막힘뚫기로 **진행을 구조화**(퍼실리테이터 대체). 초기 문제 정면.
- 첫 대면 3병목(발언 쏠림 / 비슷한 아이디어 / 결과 증발) 각각에 대응 단계 존재.
- "첫 대면 = 서로 모름" → **프로필 + 팀 스킬맵**으로 정면 대응(최근 추가).

**갭(정직하게)**
- 우리 흐름은 **"주제·아이디어 결정"**에 강하게 쏠려 있음. 그런데 "팀플 첫 대면 비효율"은 주제뿐 아니라 **역할 분담 안 됨 / 다음에 뭘 할지 안 정해짐 / 기대치·헌신 수준 불일치**도 큰 몫.
- 우리는 범위를 "주제 확정까지"로 **의도적으로 고정**(목적 확대 우려). 그래서 **"첫 회의가 끝났을 때 팀이 실제로 굴러가는가"는 절반만** 충족.
- **팀 스킬맵**을 넣었지만 지금은 발산 각도로만 쓰고 **역할 분담으로 연결 안 됨** → 첫 대면 완결성이 아쉬움.

**Claude가 제안하는 발전 방향(초기 문제 더 만족)**
1. **세션 끝에 "첫 회의 마무리" 산출물** — 주제 + (스킬맵 기반)역할 제안 + 액션 1~2개 + 다음 모임/연락. (보고서에 얹어 범위 최소화)
2. **팀 스킬맵 → 역할 제안 연결**(서버 공백 → 학습/축소 결정 지원).
3. 아이스브레이킹을 첫 대면용("서로 알기")으로 강화.
4. (선택) 초경량 기대치 맞추기(가용 시간/목표 수준).

## 4. Grok에게 — 검수 질문
1. **초기 문제 적합성:** 현재 흐름이 "팀플 첫 대면 비효율"을 충분히 푸는가? 우리가 "주제 결정"에 집중하고 **역할·다음스텝·기대치는 범위 밖**으로 둔 게 맞는 절제인가, 아니면 초기 문제를 반만 푸는 것인가?
2. **범위의 경계:** 위 발전 방향 1~2(마무리 산출물·역할 제안)를 넣는 게 **초기 문제 완결**인가, 아니면 우리가 경계했던 **"목적 확대"**인가? 넣는다면 어디까지가 안전선인가?
3. **AI/LLM 사용 적절성:** 초기 문제(진행 능력 부족)에 대해 우리의 AI 사용(작업별 라우팅 + 막힘감지 개입 + 검색 분리 + 팀 스킬맵)이 **과한가/부족한가/엉뚱한가?** 특히 "막힘 감지 신호(유사도·발언분포)"를 오프라인·소규모에서 신뢰성 있게 쓸 수 있나?
4. **AI가 사람 진행을 대체 vs 보조:** 진행 능력이 부족한 팀에게 AI가 어디까지 주도해야 하나? 지금은 "AI 제안 → 진행자 수락"인데, 진행자도 초보인 상황에서 이 균형이 맞나?
5. **정직성:** "성능 우위 미검증", "시연용 표기", 비용 기준선(단일 저가모델 대비) — 초기 문제 해결 주장에서 과장 위험은 없나?

## 5. 정직성 셀프체크
- 현실성/비용은 실측(Langfuse/promptfoo/Brave)이나 **"첫 대면 비효율을 실제로 줄인다"는 실사용 데이터는 아직 없음**(외부 팀 세션 미수집).
- 팀 스킬맵·막힘뚫기 재설계는 **설계·목업 단계**, 일부 배선 남음(프로필 세부 태그·diagnose 신호·역할 연결 미구현).
- 범위를 "주제 확정"으로 좁힌 것은 의도적 선택 — 초기 문제의 나머지 절반을 안 푸는 것을 감수한 것. 이 판단 자체가 검수 대상.
