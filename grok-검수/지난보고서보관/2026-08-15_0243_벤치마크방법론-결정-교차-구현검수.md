## 0. 요약 판정

원자료와 발표 표의 **숫자(토큰·비용·배수)는 대체로 일치**한다. 「이론 1순위 Qwen이 실측에서 한국어 불안정 → 탈락」서사는 **정직하고 타당**하다.  
ice=**Gemini-2.5-Flash-Lite**, flagship=**추론 OFF/비추론** 권고는 설계 A·비용 스토리와 **정합**하나, 창의성 「덜 알려진 오픈모델」서사는 **Solar 등으로 재구성**해야 한다(발표자료 §5와 동일 결론 — 승인).

방법론은 **발표 예비 근거로는 합격**, 단 표본·단일 프롬프트·품질 루브릭·「최속」주장에서 **Medium** 허점이 있다.  
구현 반영(S1·kind별 max_tokens·라벨=슬러그)은 요청서대로 adapter **미변경** — **아직 미반영**. 반영 시 주의점은 §4.

**Blocker 0 / High 0 / Medium 6 / Low 4 / Question 1**

## 1. [요청①] 방법론 검수 — `bench.mjs` / `bench-consistency.mjs`

### 1-1. 잘된 점 (발표 근거로 쓸 수 있는 부분)

| 요소 | 평가 |
|------|------|
| `usage: { include: true }` → `usage.cost` | §5 「실측」에 맞는 비용 근거. 티어 단가 추정이 아님 ✅ |
| 추론누수 `reasoningLen` | ON/OFF·Nemotron 낭비를 **숫자로** 보여 줌 ✅ |
| 동일 프롬프트·시스템·delimiter | adapter 실서비스 프롬프트와 유사 → 외적 타당성 ✅ |
| ice 일관성 3회 | 단발 행운을 걸러 Qwen 탈락을 정당화 ✅ |
| 원자료 JSON 보존 | 재현·감사 가능 ✅ |
| 레이트리밋 sleep | 실무적 OK |

**원자료 ↔ 발표 숫자 대조 (샘플):** Flash-Lite ice `$0.0000153`/out22/550ms, Nemotron out330/reasoning1620, GLM analyze ON `$0.0046108` vs OFF `$0.000494` (≈9.3×), report ON `$0.0035922` vs Gemini `$0.0001647` (≈21.8×) — **표와 일치**.

### 1-2. 방법론 한계 (Medium 위주)

| ID | 심각도 | 지적 |
|----|--------|------|
| M1 | **Medium** | **표본 n=3, 프롬프트 1개.** ice 결론을 「한국어 신뢰도」일반화하기엔 얇다. 발표 시 「이 과제·이 프롬프트·3회」로 한정 고지할 것. 이상: goals ≥5·reps ≥5 또는 temp≤0.3 |
| M2 | **Medium** | **temperature 0.7** — 일관성 테스트에 불리. Qwen 탈락은 실재(영·중 혼입)하나, temp 0에서도 깨지는지는 미검증. 「모델 결함 vs 샘플링」분리 부족 |
| M3 | **Medium** | `hasHanzi`만으로 「정상 한국어」를 자동 판정하면 **영어 혼입(run1)을 놓침**. 발표의 1/3은 **사람 판독**이 맞음. 자동 지표를 쓸 거면 한글 비율·ASCII 비율도 넣을 것 |
| M4 | **Medium** | 발표 「Flash-Lite **최속**」— shootout 1회 550ms는 맞지만, consistency **평균 1153ms > GPT-4o-mini 852ms**. 최속 주장은 **과하거나 조건 한정** 필요(「단발 샷」또는 표에서 제거) |
| M5 | **Medium** | flagship **품질**은 비용만 비교. 「양호」는 주관. 스키마/ rubrics 없으면 §5·§7과 약함. 최소: 테마 개수·한국어·길이 체크리스트 |
| M6 | **Low** | ice `max_tokens: 512` — 추론 모델 낭비 측정엔 유리, 실서비스 권고(64~128)와 다름. 표에 「벤치 상한」명시 |
| M7 | **Low** | `:free` Nemotron — $0·가능 로깅. 비용 스토리 분모에 넣지 말 것(이미 별도 행이면 OK) |
| M8 | **Low** | report에 **GLM 추론 OFF** 행 없음 — analyze만 ON/OFF. 대칭 비교면 설득력↑ |
| M9 | **Low** | Qwen은 pipeline keyword/idea에서 한국어 OK — **ice 특화 실패**로 서술하는 편이 정확(전 kind 금지로 읽히면 과장) |

**방법론 판정:** 예비·심사 발표용으로 **채택 가능**. 단 M1·M4·M5는 슬라이드 문구를 조이거나 후속 벤치로 메울 것.

## 2. [요청②] 결정 검수 — ice=Flash-Lite · flagship=추론OFF

### 2-1. ice = Gemini-2.5-Flash-Lite (+ 대안 4o-mini)

| 축 | 판정 |
|----|------|
| 설계 A (small·비추론) | ✅ 실측과 일치. Nemotron/Llama-3B 탈락 정당 |
| §5 정직성 | ✅ 「이론 Qwen → 실측 탈락」을 공개하는 것은 **가산점** |
| 비용 스토리 | ✅ Flash-Lite가 슛아웃에서 최저 유료 비용 |
| 창의성 「덜 알려진 오픈」 | ⚠️ **트레이드오프.** Gemini는 유명 상용. 오픈 스토리를 접는 것은 정직하나 차별성 약화 |

**권고 (정직성 유지하며 차별성 보강):**
- **라우팅 엔진 + 실측 절감**이 창의성·사업성의 본체 (모델 브랜드가 아님).
- 「덜 알려진」축은 **Solar-Pro-3/4 (ux·국산)** · (후속) 검증된 오픈 instruct로 유지.
- 슬라이드 문구 예: 「유명 모델 하나에 몰지 않고, **작업별 실측으로** 저가 비추론을 고른다 — ice는 Flash-Lite」.

**결정: ice=Flash-Lite 승인.** GPT-4o-mini는 안정 대안(일관성 3/3, 약간 비쌈) — 페일오버 후보로 적합.

### 2-2. flagship = 추론 OFF 또는 비추론 Gemini

| 축 | 판정 |
|----|------|
| 비용 | ✅ 9~22×는 원자료로 뒷받침. 「추론=기본 ON이면 small/flagship 의미 붕괴」이전 검수와 동일 |
| 설계 | ✅ analyze/report에 추론을 **옵션**으로 두는 것은 캐스케이드·승격과 같은 「필요할 때만 비싸게」 |
| 정직성 | ⚠️ OFF로 바꾸면 출력 짧아짐(analyze 2065→194). **품질 게이트 없이** 「같다」고 말하면 과장. 「비용↓, 형식은 충분 / 깊은 추론은 ON」이 정직 |

**결정: 추론 OFF 기본 + 품질 필요 시 ON — 승인.** registry/adapter에 `reasoning: { enabled: false }`를 flagship 기본으로 박을 것.

### 2-3. Qwen 탈락

일관성 run: 영어혼입 / 정상 / 중국어 — **1/3 정상** 서술 OK.  
ice 프로덕션 1순위에서 제외는 **타당**. keyword 등에서의 재시험은 선택(M9).

## 3. [요청③] 독립 교차 검증 (리더보드·시장 — API 재호출 없음)

### 3-1. 교차 결과

| 출처 | ice/한국어 함의 |
|------|----------------|
| [BenchLM Korean LLM](https://benchlm.ai/leaderboards/korean-llm) (2026-07) | **Solar** 지역 1위(Avg ~80.1). HyperCLOVA·EXAONE 상위 — **국산 스토리=Solar가 리더보드와 정합** |
| [BenchLM Korean benchmarks 혼합](https://benchlm.ai/leaderboards/korean-benchmarks) | 글로벌 프론티어도 한국어 강함. Flash-Lite급은 「한국어 전문」1위가 아니라 **가성비·짧은 생성** 포지션 |
| 가격 비교(Flash-Lite vs 4o-mini) | Flash-Lite가 입력·출력 단가 일반적으로 저렴 — 벤치 비용 순위와 **모순 없음** |
| Solar Pro 4 on OpenRouter | 국산·에이전트·한국어 강화 보도 — **ux/스토리 후보로 Pro-3 실측 + Pro-4 A/B** 가치 |

### 3-2. 반례·추가 후보 (벤치에 없거나 부족)

| 후보 | 왜 볼 가치 | 비고 |
|------|------------|------|
| **`upstage/solar-pro-3` / `solar-pro4`를 ice 일관성 3회** | idea ux만 1회. ice 안정성을 Flash-Lite와 직접 비교 안 함 | 단가↑ 가능 — 「국산 ice」vs 「가성비 ice」이원화 가능 |
| `google/gemini-2.5-flash` (non-Lite) | 이미 슛아웃에 있음 — Lite 대비 ~5× — 페일오버만 |
| Qwen + 「한국어만·한자 금지」시스템 + **temp 0** | 탈락 재확인용. 통과해도 기본 불안정 이력이 있어 1순위 복귀는 비권고 | |
| HyperCLOVA 등 | 한국어 강하나 **OR 미등재**면 오케스트레이터 전략 밖 | |

**교차 결론:** Flash-Lite ice 권고를 뒤집을 **강한 반례는 없음**. 오히려 Solar를 스토리·ux에 더 올려도 됨. Qwen 7B를 ice 1순위로 되돌릴 교차 근거는 **없음**.

## 4. [요청④] 다음 구현 반영 확인

요청서: adapter 실호출은 **미변경**, 벤치만 추가. 코드 재확인 결과:

| 이전 검수 항목 | 현재 코드 | 반영? | 구현 시 주의 |
|----------------|-----------|-------|--------------|
| **S1** 멱등=실호출 스킵 | `orchestrate`: `already`여도 **`callModel` 호출** | ❌ **미반영** | `if (already) { return cached/summary }` — 미터만 스킵하면 High 비용 버그 유지 |
| kind별 `max_tokens` | adapter `max_tokens: 1024` 고정 | ❌ | 벤치 MAXTOK 참고: ice 64~128, keyword/idea 256, analyze/report 512~1500. **추론 OFF여도** ice에 1024는 낭비 |
| 라벨=슬러그 동기화 | registry `ice: Nemotron-Nano`, Solar-Pro-**2**, GLM-**5.2** vs 벤치 GLM-4.6 / Flash-Lite | ❌ | 권고 반영 시 라벨을 `Gemini-2.5-Flash-Lite` 등으로 **동시** 변경. 주석 `solar-pro-2` 폐기 |
| `reasoning: { enabled: false }` | adapter에 없음 | ❌ | flagship 기본 OFF — 벤치 `noReason`와 동일 |
| meter in/out·pricingMode | 이전 Medium 잔여 | (이번 범위 외) | 실측 전환 시 함께 |

**판정:** 「벤치 결과를 registry/adapter에 넣기 직전」상태. 넣기만 하고 S1·max_tokens·reasoning OFF를 빼먹으면 **실측 이득이 코드에서 사라지거나 이중과금**으로 상쇄된다.

**Question:** flagship 라벨을 `GLM-4.6`으로 내릴지, 벤치 슬러그 `z-ai/glm-4.6`만 쓰고 UI는 `GLM` 유지할지 — 정직성상 **슬러그·메이저 버전을 라벨에 반영** 권장.
