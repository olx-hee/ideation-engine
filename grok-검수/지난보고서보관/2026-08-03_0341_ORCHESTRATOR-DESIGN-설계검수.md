## 0. 요약 판정

문서의 큰 방향(A=세션 정적 라우팅, 저가 라우팅 판단 불변, 측정으로 절감 증명, 키 서버 전용)은 **타당하고 전략 보고서와도 일치**한다.  
하이브리드(규칙+저가분류기+캐스케이드)도 **실무적으로 옳은 기본형**이다.

다만 **P1에서 B를 ‘목업 자리’로 둘 때 범위를 엄격히 제한**하지 않으면 과설계로 미끄러지고, **캐스케이드·분류기·재시도가 절감 슬라이드를 잠식**할 수 있으며, **OpenAI 호환 가정만으로는 어댑터가 깨진다**. 평가·톤·지연·다공급사 프라이버시는 문서에 거의 없어 **지금 설계에 자리를 박아 두는 것**을 권한다.

**Blocker 0 / High 3 / Medium 5 / Low 2 / Question 2**  
(설계 리스크 등급 — 출시 차단이 아니라 “이 방향으로 가면 발표·상용에서 깨질 지점”)

## 1. §7-1 — 「쉬움 vs 복잡함」하이브리드 타당성

### 판정: **타당. MVP는 더 단순하게 시작해도 됨.**

제안(A=①정적, B=③저가분류기+④캐스케이드 안전망, 라우팅 판단은 저가/규칙만)은 업계 티어 라우팅·캐스케이드 패턴과 맞고, 문서의 자충수 경고(고가 분류기 금지)도 정확하다.

**더 낫거나 단순한 신호 (우선순위)**

| 우선 | 신호 | 비고 |
|------|------|------|
| 1 | **`kind` 정적 표만** (A 전부) | 세션이 이미 분해됨. P1~P2의 난이도 엔진은 사실상 이것만으로 충분 |
| 2 | **출력 스키마 복잡도** (JSON 필드 수, enum) | 보고서/테마=승격 후보, 키워드 카드=저가 고정 |
| 3 | **입력 길이·세션 로그 첨부량** | 휴리스틱 ② — 길면 mid, 짧으면 small (LLM 불필요) |
| 4 | **사용자/플랜 플래그** | 데모·무료는 small 강제 (비용 폭주 방지) |
| 5 | 저가 분류기·캐스케이드 | B·애매 kind에만. P4에서 본격화 |

**캐스케이드가 절감을 잠식할 위험 — 실재함 (High로 설계에 적어둘 것)**

- 승격률이 높아지면 평균 비용 ≈ `cheap + expensive`에 수렴 → “저가 n + 고가 m” 서사가 무너짐.
- 품질 체커가 빡세면 **거의 매 콜 이중 과금**; 헐거우면 저가 불량이 사용자에게 노출.
- 체커 자체를 LLM으로 돌리면 **3콜**(저가생성+판정+고가) 위험.

**설계에 넣을 가드레일 (권고)**
1. `escalate_rate` 상한 (예: kind별 15% 초과 시 알림·규칙 재튜닝)  
2. 캐스케이드는 **허용 kind 화이트리스트**만 (예: analyze/report/critique). ice 카드는 캐스케이드 금지  
3. 승격 **최대 1회**, 같은 티어 재시도만 1회  
4. 체커는 가능하면 **규칙/스키마 검증** 우선, LLM 판정은 최후  
5. 미터에 `escalated: true` 필수로 로깅 → 절감 화면에서 **이중호출분을 분리 표시**

**§4 하이브리드에 대한 한 줄:**  
방향 OK. 다만 **P1~P2는 ①(+가벼운 ②)만으로 “난이도 문제”를 닫고**, ③④는 B/P4 안전망으로 명시하는 편이 단순하고 발표도 정직하다.

## 2. §7-2 — A+B 공유 코어가 과설계인가 / B를 P1 목업에 둘지

### 판정: **코어 공유 자체는 과설계 아님. P1의 B ‘자리’는 얇은 인터페이스만.**

```
레지스트리(역할·티어·model id) + 어댑터 + 실행 + 비용 미터
```
이 네 조각은 A만 해도 어차피 필요하다. B가 나중에 “같은 입구로 서브작업을 넣는다”는 그림은 자연스럽다.

**과설계로 미끄러지는 지점**
- P1에서 분류기 프롬프트·서브작업 온톨로지·캐스케이드 정책을 **반쯤 구현**하는 것  
- B용 UI/API를 A보다 먼저 키우는 것  
- “분해 레이어”를 추상화하느라 세션 `kind` 표를 간접 호출만 하게 만드는 것  

**권고**
- **P1:** A를 끝까지(규칙 표 + 미터 + “누가 뭘 했는지/절감” 화면). B는  
  `plan(request) → [{kind, …}]` **스텁이 고정 목업 배열을 반환**하는 수준만 (또는 인터페이스 주석만).  
- **B 본구현은 P4 유지**가 맞다. 지금 목업 자리는 “코어가 B도 먹을 수 있다”는 **확장 증명용 1슬라이드**면 충분.  
- 발표에서 B를 크게 팔거면 P1 목업 결과를 **가짜 분해로 명시** (정직성 — 전략 보고서와 동일 원칙).

**한 줄:** 공유 코어 = 얇게 유지하면 과설계 아님. **B 엔진을 P1에 끌어올리지 말 것.**

## 3. §7-3 — 비용 절감 주장을 정직하게 유지할 함정

문서 §5가 이미 핵심(오버헤드 < 절약, 분류기 저가, 측정)을 짚었다. **추가로 박아 둘 함정:**

### [High] 베이스라인 정의가 흐리면 슬라이드가 “조작”으로 읽힘
- “전부 고가 $Y”가 **실제로 쓰이지 않을 가상 비교**임을 UI에 명시할 것.  
- 공정 비교: **동일 세션 로그를 두 번 재생**(또는 동일 kind 시퀀스) — 라우팅 on/off.  
- 품질을 무시한 채 싼 모델만 쓰면 절감은 커도 제품이 나빠짐 → **절감% 옆에 승격률·스키마 실패율을 같이**.

### [High] 숨은 이중·삼중 과금
- 캐스케이드 승격, JSON 파싱 실패 재시도, 오케스트레이터/분류기 콜, 교차검증 2nd 모델  
- 미터 필드 권장: `purpose: route|generate|escalate|verify|repair`  
- 절감 공식 분모·분자에 **purpose=generate만** 넣을지, 전부 넣을지 **문서에 고정**.

### [Medium] 목업 단가 vs 실측 단가
- P1 목업 단가로 “Z% 절감”을 보여주면 데모는 되지만, P2 이후 **숫자가 흔들림**.  
- UI: `추정(목업 단가)` / `실측` 배지 분리. 발표 슬라이드에도 출처 표기.

### [Medium] 토크나이저·제공자 과금 단위
- 한국어·혼합 텍스트는 영어보다 토큰↑ → 절감률이 영문 벤치와 다름.  
- provider별 billing tokenizer ≠ 로컬 추정 → **가능하면 응답의 usage 필드를 진실로**.  
- 최소 요금·실패한 요청·스트리밍 부분 과금 정책.

### [Medium] 캐시·배치를 절감에 넣는지
- prompt caching 할인분을 “우리 라우팅 덕”으로 합산하면 과장.  
- **라우팅 절감**과 **캐시 절감**을 라인 아이템으로 분리.

### [Low] 무료 티어(NIM/Groq/Studio) = $0으로 영원히 가정
- 데모엔 좋지만 상용 견적에 넣으면 사고. 절감 화면과 **사업 계획용 $/세션**을 분리.

**정직성 체크리스트 (§5 보강안)**  
`[ ]` 베이스라인 정의 문구  
`[ ]` escalate/repair/verify 콜 분리 집계  
`[ ]` 목업/실측 배지  
`[ ]` usage 기반 토큰  
`[ ]` 캐시 절감 별도  
`[ ]` escalate_rate 공개

## 4. §7-4 — 공급사 어댑터 (OpenAI 호환 가정)

### 판정: **기본 전략(OpenRouter + 보완)은 좋음. ‘호환=동일’은 위험.**

**호환이 깨지거나 미묘하게 다른 예외**
| 공급사 | 주의 |
|--------|------|
| Anthropic 네이티브 | Messages API, 헤더·시스템 역할 형식 다름. OpenRouter 경유 시 완화 |
| Google AI Studio | `generateContent` / safety 설정. OpenAI 호환 프록시 품질 제각각 |
| NVIDIA NIM | API 키 헤더(`NVAPI` 등), 모델 id 경로, rate limit·콜드스타트 |
| Groq | 모델 슬러그·JSON mode·툴콜 지원 범위가 좁을 수 있음 |
| 공통 | `response_format`/`json_schema`, tool_calls, max_tokens vs max_completion_tokens, 스트림 청크 |

**파싱 실패 대비 (설계에 명시 권고)**
1. **Zod(또는 JSON Schema)로 엄격 검증** — 실패는 예외가 아니라 1급 결과  
2. **repair 1회**: 같은 티어에 “스키마만 고쳐” 재요청 (escalate와 분리해 미터링)  
3. 그래도 실패 → (a) 허용 kind만 캐스케이드 승격 (b) 아니면 안전한 폴백 UI(시연 샘플/재시도 버튼)  
4. **타임아웃·429**은 provider별 재시도 백오프 + 페일오버 model (같은 티어 다른 공급사)  
5. 어댑터 인터페이스는 OpenAI 모양이되, **내부적으로 provider capability 플래그**  
   (`supportsJsonSchema`, `supportsTools`, `authStyle`)를 레지스트리에 두기  

**보안:** 키·베이스 URL은 서버 env만. 프론트에는 `modelLabel`·`tier`·비용만. (문서 §2와 동일 — 유지)

## 5. §7-5 — 놓친 리스크

문서에 약하거나 없는 항목:

### [High] 평가 체계 부재
라우팅·캐스케이드를 튜닝할 **골든 세션 세트 / 자동 채점(스키마 통과율, 사람 선호 A/B)** 없으면  
“적재적소”가 감이 되고, 절감만 최적화하다 품질이 무너짐.  
→ P2 전에 **최소 10개 고정 세션 픽스처 + kind별 성공 기준**을 설계 문서에 한 절 추가 권고.

### [Medium] 지연 UX 스택
분류기(+옵션) + 생성(+옵션 승격) + 검증이 **직렬**이면 카드 하나가 수 초~십 수 초.  
→ kind별 **목표 p95**, 스켈레톤/스트리밍, “승격 중” 표시, ice류는 캐스케이드 금지와 연계.

### [Medium] 톤·페르소나 불일치
모델이 바뀌면 말투가 달라 “여러 AI”가 장점이 아니라 **제품 퀄 저하**로 보임.  
→ 공통 **스타일 카드**(존댓말, 금지 이모지, 길이) + 가능하면 후처리 정규화 한 겹.

### [Medium] 다공급사 프라이버시·약관
아이스/아이디어 원문이 OpenRouter·NIM·Groq 등으로 분기.  
학교·해커톤 맥락에서 **데이터 학습 이용·보관** 고지·옵트인 없으면 상용·발표 Q&A에서 터짐.  
→ 공급사별 data retention 표를 설계 부록에.

### [Medium] 데모 재현성·무료 티어 한도
NIM/Groq/Studio 한도·콜드스타트로 **발표 직전 실패**.  
→ 데모 프로파일: “오프라인 목업 단가 재생” 스위치 + 실호출 프로파일 분리 (P1 미터와 맞음).

### [Low] 프롬프트 인젝션
사용자 제출 텍스트가 오케스트레이터/분류기 프롬프트에 그대로 들어가면 티어 조작·지시 탈취.  
→ 사용자 콘텐츠는 **delimiter + 읽기 전용 블록**, 분류기 출력은 스키마로만 수용.

### [Low] OpenRouter 단일 장애점
기본 레이어 집중 → 보완 공급사로의 **자동 페일오버 경로**를 레지스트리에 미리.

### [Question] 교차검증(§1-4)의 호출 예산
품질 차별의 핵심인데 비용·지연 예산이 §4~5에 없음.  
→ “세션당 verify ≤ N회, analyze/report만”처럼 **쿼터를 A 표에 명시**할지?

### [Question] 발표 메시지 vs P1 범위
§1은 분해·절감·집계·교차검증 넷인데 P1은 미터+A 규칙.  
→ 슬라이드에서 P1이 증명하는 것(라우팅+절감 추정)과 P4 과제를 **명시적으로 쪼갤지?** (정직성)

## 6. §7 질문별 직접 답 (복붙용)

**Q1. 하이브리드 타당한가?**  
→ 예. 다만 난이도 엔진의 본체는 A의 **정적 kind 표**. 분류기+캐스케이드는 B/애매 케이스 안전망. 캐스케이드는 승격률 상한·kind 화이트리스트·미터 분리 없으면 절감 잠식 위험 큼.

**Q2. A+B 공유 코어 과설계? B를 P1 목업?**  
→ 얇은 코어(레지스트리·어댑터·미터) 공유는 적절. B는 P1에 **스텁/고정 목업만**, 엔진은 P4. 반쯤 구현하지 말 것.

**Q3. 절감 정직성 함정?**  
→ 베이스라인 문구, escalate/repair/verify 분리, 목업vs실측, usage 토큰, 캐시 절감 분리, 한국어 토큰, 무료티어 $0 영구 가정 금지.

**Q4. 어댑터 예외·파싱?**  
→ capability 플래그, 스키마 검증, 동티어 repair 1회, 제한적 승격, 429/타임아웃 페일오버. Anthropic/Gemini/NIM 네이티브를 “순수 OpenAI 1코드”로 가정하지 말 것.

**Q5. 놓친 리스크?**  
→ 평가 픽스처, 지연 UX, 톤 카드, 다공급사 프라이버시, 데모 한도/재현성, 인젝션, OpenRouter SPOF, 교차검증 예산, P1이 증명하는 범위의 정직한 슬라이드 분할.

## 7. 설계에 대한 총평 (개발·발표 팀에)

| 잘된 점 | 보강할 점 |
|---------|-----------|
| 네 가지 차별점 + 정직성(“실제로 다른 모델”) | P1 범위와 §1 네 기둥의 매핑을 표로 |
| A/B 공유 코어 그림이 명확 | B 목업의 **금지 범위**(분류기·캐스케이드 미구현) |
| 라우팅 판단=저가 불변 규칙 | escalate_rate·purpose 미터링 |
| 측정=제품 기능으로 승격 | 평가 세트·톤·프라이버시·데모 프로파일 절 |
