## 판정 한 줄

**맞다. 재측정해야 한다. 단 "전부 다시"가 아니라 4개만이고, 재는 축이 바뀌어야 한다.**  
이유는 **모델이 변해서가 아니라 작업의 모양이 변해서**다. 새 작업 14개(계산 1개 제외) 중 **기존 측정을 승계할 수 있는 건 4개뿐**이고, 나머지는 기존 kind에 대응이 없다. 게다가 새 화면은 **지연·스키마 준수·검색 근거**를 요구하는데, 기존 벤치는 **품질·비용만** 쟀다.  
그리고 2개(#8·#13)는 **측정 문제가 아니라 방향 결정 문제**다 — 여기부터 정리해야 한다.

**보안:** 이번 범위는 방향 검수 — 신규 구현 없음. 다만 아래 **프롬프트 주입(검색 결과 → LLM)** 한 건은 설계 단계에서 못 박을 것.

## 2. 왜 기존 결과를 그대로 못 쓰나 — 축이 늘었다

기존 벤치(confound·rematch·heavy-analyze·report-retest·verify-bench)가 잰 것은 **품질 점수 + 비용**이다. 새 화면은 여기에 **세 축**을 더 요구한다.

[High] **지연(latency)을 한 번도 안 쟀다**  
· #1 꼬리질문·#3 뜻풀이는 **요청 안에서 사람이 기다린다**(docs/05 "요청 안"). 품질·비용 1위라도 p95가 8초면 인터뷰 UX가 무너진다.  
· 제안: 이 둘은 **품질이 아니라 p50/p95로** 모델을 고른다. 기존 표의 Flash-Lite가 유력하지만 **재확인은 필요**.

[High] **스키마 준수를 안 쟀다**  
· 새 작업은 전부 화면이 그리는 **고정 필드**를 돌려준다(#7 등급+6관점, #5 그룹 3~5개, #11 파트+후보+대안). 파싱 실패 = 화면 깨짐.  
· 기존 벤치는 산문 품질을 심판으로 쟀지 **JSON 스키마 준수율**을 잰 적이 없다.  
· 제안: 모든 작업의 1차 지표를 **파싱 성공률·필수 필드 충족률**로. 이건 심판 LLM 없이 **자동·거의 0원**으로 잰다.

[High] **검색 근거 충실도를 안 쟀다**  
· docs/05 "꼭 지킬 것 1. 지어내지 않기" — #2·#7은 **검색 결과에 있는 것만** 쓰고 링크를 붙여야 한다.  
· "아이디어를 잘 낸다"와 "검색 결과 밖을 말하지 않는다"는 **다른 능력**이다. 전자로 뽑은 모델이 후자에서 질 수 있다.  
· 제안: **출력 주장 중 검색 결과에 없는 것의 비율 + 링크 유무**를 자동 대조.

## 3. 측정이 아니라 **방향 결정**이 먼저인 2개

[High] **#8 "AI가 모은 아이디어"** — 우리가 반증·기각한 자동 종합의 재등장  
· 문제: 좋은 점 받은 아이디어들 → **AI가 새 아이디어 ≤2개 생성** → 그게 **투표 후보로 올라간다**.  
· 우리 이력: 이종 자동 합성이 품질 우위 없음(confound·rematch), 1210 검수에서 "AI 묶기는 **fallback**, 기본 아님"으로 정리.  
· **성립 조건은 이미 충족**돼 있다 — 입력이 사람 아이디어, 출처(어디서 가져왔는지) 표기, 사람이 투표로 선택. 0145·1210 기준으로 **허용 범위 안**이다.  
· 지키지 않으면 무너지는 선: (a) 목록에서 **기본 선택·상단 고정 금지**, (b) "AI가 합쳐서 더 좋다"로 발표 금지, (c) 이 후보가 1위가 되면 **보고서에 AI 생성임을 명시**.  
· → **측정 대상이 아니라 UX·문구 제약으로 고정할 것.**

[High] **#13 "겹친 후보 판단"** — AI가 사람 배치를 정하고 근거는 비공개  
· 문제: 같은 파트 후보들의 답을 AI가 보고 **누가 맡을지 결정**, 근거는 비공개. 1210에서 합의한 "**AI가 사람을 심판하지 않는다**"와 정면으로 부딪친다.  
· 완화되어 있는 것: 팀장이 9-4에서 고칠 수 있고, 답 원문은 끝까지 비공개(익명 규칙).  
· 그래도 **기본값이 "AI가 정함"**이고 **근거를 아무도 못 본다**는 조합은 위험하다. 팀장이 뭘 근거로 고칠지 알 수 없다.  
· 제안: (a) 결과를 "결정"이 아니라 **"추천 + 근거 요약(익명 유지)"**으로, (b) 팀장 화면에는 **근거 한 줄 노출**, (c) 동점이면 **AI가 고르지 말고 팀장에게 넘김**.  
· → 이걸 정한 뒤에 모델을 재야 한다. 순서가 반대면 또 다시 잰다.

## 4. 재측정 범위 — 4개만

| 순위 | 작업 | 왜 이것부터 | 측정 축 |
|------|------|-------------|---------|
| **1** | #7 AI 검증·현실성 | 가장 무겁고 **틀리면 신뢰가 바로 깨짐**(등급 3단계가 화면 전면). 검색 근거 필수 | 근거 충실도 · 스키마 · 등급 일관성 · 비용 |
| **2** | #11 파트 나누기 + 후보 | 완전 신규 · **사람 배치의 출발점** · 팀 스킬만으로 판단 | 스키마 · 후보 타당성(사람 1~2명) · 없는 스킬 대안 품질 |
| **3** | #15 보고서 | 기존 `report`=DeepSeek 1위였으나 **분량·구조가 3배**(A4 2쪽 + 워크플로우 4단계). 결론 유지되는지만 확인 | 완결성 · 스키마 · 비용 |
| **4** | #1 · #3 실시간 2개 | 사람이 기다리는 유일한 경로 | **p50/p95 지연** (품질은 통과/탈락만) |

**승계(재측정 안 함):** #4 재료 뽑기 · #5 묶기 · #6 추천 · #10 · #12 → 기존 `keyword`/`analyze`/`idea` 결론 유지, **스키마 준수만 한 번 확인**.

**하지 말 것:** 창의 품질 대형 벤치 재도전 · 모델 zoo 확장 · LLM-judge 점수 자랑 (1855·2334·2228에서 이미 기각).

## 5. 측정 방법 — 싸고 자동으로

이전 벤치의 교훈은 "**심판 LLM로 창의 점수 매기기에 과투자하지 말 것**"이었다. 새 측정은 **대부분 사람도 심판 LLM도 필요 없다.**

| 지표 | 방법 | 비용 |
|------|------|------|
| 스키마 준수율 | N회 호출 → JSON 파싱 + 필수 필드 검사 | 호출비만 |
| 지연 p50/p95 | 같은 호출에서 시간 기록 | 0 |
| 근거 충실도 | 출력 주장 ↔ 검색 결과 자동 대조, URL 유무 | 0 |
| 세션당 비용 | **이미 있는 meter** 활용 | 0 |
| 사람 판단 | #7 등급 · #11 파트만, **골든 세션 1~2개** | 사람 30분 |

## 6. 언제 하나 — 순서가 중요하다

지금 바로 전부 재면 **또 버리게 된다.** 백엔드 구현 전이라 프롬프트·입출력이 확정되지 않았고, 새 작업 8개는 **스키마가 곧 계약**이기 때문이다.

**권장 순서**

1. **지금** — #8·#13 **방향 결정**(위 3장) + 작업 15개의 **입출력 스키마 확정**. 모델은 아직 안 정해도 됨.
2. **지금 (병행 가능)** — #1·#3 **지연 측정**. 입출력이 단순해 스키마 확정 전에도 잴 수 있다.
3. **레지스트리 재작성** — `registry.js`의 kind를 **작업 15개 기준으로** 다시 쓴다. (아래 정직성 항목)
4. **백엔드가 큐로 붙인 뒤** — 골든 세션 1개로 #7·#11·#15 실측 → 표 확정.

## 7. 정직성 — 지금 손 안 대면 발표에서 틀어지는 것

[High] `server/orchestrator/registry.js` — **kind 이름이 실제 작업과 안 맞는다**  
· 문제: `ice`(=발산 워커) · `idea` · `analyze` · `report` 4개로 세션을 설명하는데, 실제 제품은 **작업 15개**다. 미터(`ai-meter`)가 "어느 모델이 무엇을 했나"를 보여주는 구조라, **kind 라벨이 틀리면 발표 화면이 사실과 다른 말을 한다.**  
· 재현: 발표에서 "ice = Flash-Lite가 아이스브레이킹 담당"이라 말하지만, 실제 아이스브레이킹은 꼬리질문·뜻풀이·재료뽑기·묶기 **4개 작업**이고 모델도 갈릴 수 있다.  
· 제안: 레지스트리를 **작업 id 기준**으로 재작성하고, 미터 purpose를 거기에 맞춘다. 이건 측정과 별개로 **지금 해야** 한다.

[Medium] docs/05의 모델 칸이 "확정 아님"으로 표기된 것 — **정직해서 좋다.** 재측정 전까지 이 표기를 유지할 것. 백엔드에 "이걸로 확정"이라고 말하지 말 것.

[Medium·보안] **검색 결과 → LLM 프롬프트 주입**  
· #2·#7은 외부 검색 본문을 그대로 모델에 넣는다. 악의적 페이지가 "이전 지시를 무시하라"를 심으면 등급·요약이 오염된다.  
· 제안: 검색 본문을 **데이터 구획으로 감싸고**(사용자/시스템 지시와 분리), 출력은 **스키마 강제**, URL은 화이트리스트 도메인만 링크.

## 8. 최종 답

- **재측정 필요한가:** **예.** 단 모델이 바뀌어서가 아니라 **작업 14개 중 8개가 신규**이고, **지연·스키마·근거**라는 안 재본 축이 생겼기 때문.
- **어디까지:** **4개**(#7 검증 · #11 파트나누기 · #15 보고서 · #1·#3 지연). 나머지 5개는 기존 결론 승계.
- **먼저 할 것:** 측정이 아니라 **#8·#13 방향 결정 + 스키마 확정 + 레지스트리 kind 재작성.**
- **하지 말 것:** 창의 품질 대형 벤치 재도전 · 모델 늘리기. (이미 기각된 길)
