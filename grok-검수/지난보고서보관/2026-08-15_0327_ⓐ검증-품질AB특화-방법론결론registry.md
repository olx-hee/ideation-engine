## 0. 요약 판정

원자료 재집계 결과, 발표의 **승패·평균 overall·비용비·특화 표는 정확**하다.  
**「분업 품질 우수」불성립 · 「특화 약함」· 「비용 2.7× 저렴」** 해석은 데이터와 정합하며, 발표 프레임을 **대등 품질 + 저비용 + 다양성 + 보안**으로 재정의하는 것은 §5 정직성에 **맞다(승인)**.

registry는 데이터와 **일부 불일치**(tech↔Solar)하나, 특화 신호가 약하므로 **(b) 다양성·비용·안정성 프레임을 본체**로 두고, tech→Solar는 **잠정·표기 있는 소프트 스왑**만 권고. 전면 “측정 기반 특화 주장”은 아직 이르다.

차별성은 **유지 가능** — 단 구상의 「품질 우위·강한 특화」는 내려놓고, **세션 구조 + 실측 티어 라우팅 + 절감 정직성**이 본체여야 한다.

**Blocker 0 / High 0 / Medium 5 / Low 4 / Question 1**

## 1. [요청①] 방법론 — A/B v2 · 특화 매트릭스 · 로직

### 1-1. 원자료 ↔ 주장 숫자

| 주장 | 재집계 | 판정 |
|------|--------|------|
| 단일 5승 / 분업 4승 / 무 1 | `{ single:5, multi:4, tie:1 }` | ✅ |
| overall 4.32 vs 4.14 | 동일 | ✅ |
| 비용 $0.000809 vs $0.000302 (≈2.7×) | 0.000809 / 0.000302 ≈ **2.68×** | ✅ (반올림 OK) |
| 특화 1등·평균 표 | wins/avgScore JSON과 일치 (기술 Solar 2·4.5 등) | ✅ |

**집계/블라인드 로직:** 치명 버그 없음.  
- A/B: `singleIsA` 셔플 후 심판 JSON을 다시 매핑 — ✅  
- 특화: `shuffle` 후 `best` 인덱스로 모델 복원 — ✅  
- 관점별 wins 합 = goal 수 4 — ✅  

### 1-2. A/B v2 타당성

| 개선(이전 n=3 대비) | 평가 |
|---------------------|------|
| n=10 goals | 방향 주장에 **충분에 가까움**. 강한 우열 주장엔 여전히 통계적 여유 부족 |
| 심판 2개(GLM+Llama), 생성 비참가 | 단일 심판 편향 완화 ✅ |
| maxTok 단일 600 / 분업 4×150 | 예산 대칭 의도 ✅ |
| 실비용 `usage.cost` | §5 정합 ✅ |

**잔여 한계 (Medium):**

| ID | 심각도 | 내용 |
|----|--------|------|
| A1 | **Medium** | **모델 강도 혼입** 여전: 분업=저가 혼합 vs 단일=`gemini-2.5-flash`(분업 novel과 동일 계열). 「분업 전략」효과와 「모델 티어」가 분리되지 않음. 이상적 대조: 동일 모델×4 병렬 vs 1회, 또는 동일 단가 예산 |
| A2 | **Medium** | goal 승자는 심판 2명의 **다수결**. 1:1이면 tie — 보수적. 다만 judge JSON 파싱 실패 시 해당 심판 누락 → 1명만으로 승패 결정 가능(로그에 실패율 미집계) |
| A3 | **Low** | LLM-judge·한국어·자기스타일 편향 — 사람 스팟체크 없음(문서 §4와 동일, 인정됨) |
| A4 | **Low** | temp 0.7 — 품질 분산. 재현용 시드/temp 0.3 병행이면 발표 더 안전 |

**판정:** 「품질 우위 불성립 + 비용 우위」를 말하기에 **방법론적으로 채택 가능**. 「분업이 항상 동등」까지 단정하진 말 것(근소 단일 우위).

### 1-3. 특화 매트릭스 타당성

| 요소 | 평가 |
|------|------|
| 4×4×4 + 위치 셔플 | 설계 의도 명확 ✅ |
| **단일 심판 GLM-4.6** | **편향 위험 큼** — 결론을 「약함/잠정」으로 한정한 것은 정직 ✅ |
| n=4 goals | Solar=기술(2/4, avg 4.5)은 **탐색 신호**일 뿐. 배정 교체 근거로는 약함 |
| Flash-Lite 사업성 3/4·4.75 | 「한 모델이 두루 강함」서사를 지지 — 특화 약함과 정합 |

**단일 심판이 결론을 얼마나 지지하나:**  
「특화 **강하지 않다** / Flash-Lite가 넓게 강하다」는 **지지**.  
「tech=Solar가 **확정**」은 **지지 부족**(Medium: 과대 확정 금지).

**로직 버그:** 없음. 생성 실패 시 `"(생성 실패)"`도 채점 후보에 남을 수 있음 — 실패율 낮으면 Low.

## 2. [요청②] 결론 검수 — 재정의 프레임

| 원래 주장 | 데이터 | Grok 판정 |
|-----------|--------|-----------|
| 분업 → 성능 우수 | 단일 근소 우위 (4.32>4.14, 5>4) | 🔴 불성립 — **문서와 동의** |
| 모델×관점 강한 특화 | Flash-Lite 광역, Solar=기술만 두드러짐 | 🟠 약함 — **동의** (「없다」까지는 과함) |
| 분업 → 토큰/비용 절감 | ≈2.7× 저렴 | ✅ **확실** — 동의 |

**재정의 「대등 품질 + ~1/3 비용 + 다양성 + 보안」:**  
- §5상 **맞음·권장**. 「대등」은 엄밀히는 **실질적 동등~근소 열위**이므로 슬라이드에 **「단일 대비 평균 근소 열위(4.14 vs 4.32), 실용상 대등 수준」** 한 줄을 넣으면 더 정직.  
- 「다양성」은 품질 이득이 아니라 **산출 각도·공급사 분산·스토리**로 한정할 것(특화≠입증).  
- 「보안」은 이번 실험 변수가 아님 — **제품 하드닝 근거**로 병기 OK, A/B 결과에서 유도된 것처럼 쓰지 말 것.

**판정: 재정의 승인.** 「분업이 더 창의적/고품질」로 돌아가면 정직성 위반.

## 3. [요청③] registry 재배정 — (a) vs (b)

### 현 코드 (`ANGLE_MODELS`)

| 각도 | 현재 배정 | 특화 데이터 시사 |
|------|-----------|------------------|
| biz | Flash-Lite | Flash-Lite 최강 — **일치** |
| ux | Solar-Pro-3 | GPT-4o-mini 4.0 > Solar 3.5 — **불일치** |
| tech | GPT-4o-mini | Solar 4.5·2승 — **불일치** |
| novel | Gemini-2.5-Flash | Flash-Lite·Flash 동률권 — **대략 OK** |

### 권고: **(b) 본체 + (a)의 최소 소프트 패치**

| 옵션 | 정직성 | 사업성 | 판정 |
|------|--------|--------|------|
| **(a) 전면 측정 재배정** (ux↔tech 등 데이터 그대로) | 약한 표본을 「특화 입증」처럼 읽히게 함 → **위험** | 잦은 교체로 톤·데모 불안정 | 비권고(단독) |
| **(b) 다양성·비용·안정성** (특화 주장 안 함) | ✅ 데이터와 말 일치 | 절감·페일오버·국산 스토리 유지 | **본체** |
| **(b)+소프트** tech↔Solar만 잠정 스왑, UI/README에 「잠정·n=4·단일심판」 | 신호가 있는 한 줄만 반영 | 국산=기술 각도 스토리 | **권장 타협** |

**하지 말 것:** 전부 Flash-Lite로 단순화하면서도 발표에서 「각도별 다른 모델 특화」를 유지하는 것.  
**해도 됨:** 데모에서 모델 라벨이 다르게 보이는 **다양성 시연** — 단 「적재적소 특화」가 아니라 「검증된 안정 모델 풀에서 분산」.

**Question:** Solar를 tech로 옮기면 ux 국산 스토리가 비는데, ux는 Flash-Lite(또는 mini)로 두고 **「국산=tech」**로 스토리를 옮길지 / Solar를 ux에 남기고 tech만 데이터와 불일치 고지할지 — 발표 메시지 선택 문제. Grok 추천은 **tech→Solar 잠정 + ux→Flash-Lite 또는 mini**, 특화 문구는 빼기.

## 4. [요청④] 독립 시각 — 차별성 · 구상 수정 · 놓친 실험

### 차별성 유지되는가?

**유지된다 — 조건부로.**  
죽이는 것: 「멀티 LLM이라 단일보다 아이디어가 더 좋다」「각 각도에 특화 모델」.  
살리는 것:

1. **세션 제품** (각도 배분·방식·오프/온·영속화) — 벤치와 무관한 본체  
2. **실측 기반 티어 라우팅** (ice 저가 비추론, flagship 추론 OFF, Qwen 탈락 등) — 「이론이 아니라 재면 바뀐다」정직성  
3. **대등 품질·1/3 비용** — 사업성 슬라이드의 실증 핵  
4. **다양성·다공급사·보안(키 서버·쿼터)** — 부가축  

→ 구상 **수정은 필요**(품질우위·강한특화 축소). **프로젝트 폐기/차별성 상실은 아님.**

### 놓친·다음 실험 (우선)

1. **동일 강도 통제 A/B:** Flash-Lite×4(각도만 다름) vs Flash-Lite×1(4관점 한 프롬프트) — 분업 **구조** 효과만 분리  
2. 특화: **심판 2+**, goals ≥10, (가능하면) 사람 8~12샘플 스팟체크 후 tech=Solar 확정 여부  
3. 「다양성」조작적 정의: 임베딩/중복률로 분업 vs 단일 아이디어 겹침 측정 (품질 overall과 별개)  
4. flagship 경로(analyze/report) 품질×비용 — 이번은 **idea 발산** 중심  
5. Langfuse는 **측정 파이프 자동화**로 두되, 위 통제 실험 후에 연결하는 편이 낭비 적음  

### 구현 메모 (이번 범위 외·참고)

요청서대로 실험만. 현 코드는 ice/Flash-Lite·GLM 추론 OFF·S1 캐시·kind별 max_tokens 등이 **이미 반영된 상태**. registry 각도만 특화 데이터와 어긋남 → §3 권고.
