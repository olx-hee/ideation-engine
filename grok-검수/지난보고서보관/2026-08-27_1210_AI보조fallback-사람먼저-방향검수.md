## 1) “AI=fallback 보조”가 0145보다 나은가 / 새 함정

### 판정: **낫다. 채택 권고.**

| 0145 | 이번 |
|------|------|
| 시드 → **항상** AI 묶기 → 사람 선택 | 사람 선택 → AI **검증**; 묶기는 **예외** |
| “중간 지대”(사람 시드+AI 주제화)가 기본 | 기본은 **사람 의견이 주제 후보** — AI는 심판·생성 아님 |
| 자동종합 **체감** 위험이 구조에 상존 | 종합이 기본 경로에서 **제거** → 0145 High 구조 위험 ↓ |

**왜 나은가:** 2228의 “사람이 뻔하지 않은 답을 고르게”와 더 직결. 심사 한 줄도 **「사람이 고르고, AI는 시중·현실 체크」**로 쓸 수 있어 0145의 “AI가 묶어 주제 후보”보다 방어가 강하다. Claude 평가 1~3에 **동의**.

### 새 함정

[High] **검증 경로의 ‘다듬기’가 사실상 재작성**  
· 문제: reality가 주제 문장을 예쁘게 바꿔 확정되면 다시 “AI가 다 함”.  
· 제안: 기본 출력 = **배지(이미있음/유사/공백) + 수정점 불릿**. **원문 유지**. “이 문장으로 바꿔줘”는 **별도 사람 버튼**.

[High] **fallback 버튼이 기본 UX가 됨**  
· 문제: 팀플에서 시간 없으면 전원 ‘막혔어’ → 0145와 동일 경로.  
· 제안: UI에서 **「이 의견으로」를 primary**, 「묶어줘」는 secondary/접힘. 데모 스크립트도 사람 픽 먼저. 세션 로그에 fallback 사용 여부(정직 미터).

[Medium] **AI 없이도 끝나는 세션 → 제품 가치 공백**  
· 문제: human-first 극단이면 ChatGPT 안 쓴 구글독과 구분 안 됨.  
· 제안: 가치 서사는 **시중검색·현실성 게이트가 ‘선택 후’에 붙는 것** + 이후 발산 병렬·이견. 주제 단계에서 AI 0회여도 OK이되, **market은 선택 직후 권장(스킵 가능하되 배지로 “미검증”)** — 강제 심판 아님.

[Medium] **전원 시드 (사용자 원함) → 로비 교착** (0145 Medium 재확인, 셀프체크와 동일)  
· 제안: 철학상 전원 유지는 OK. 완화는 **대기 UI+누가 남았는지** / 온라인은 비동기 제출 후 모이면 ② / 호스트 “대필”은 라벨 강제. **최소 k로 후퇴하지 말라는 사용자 의도 존중** — 대신 교착을 UX로 드러낼 것.

## 2) 개입=사람 버튼 vs 나쁜 의견 고착 / 절제선

### 판정: **사람 버튼이 타당. AI를 ‘의견 품질 심판’으로 올리지 말 것.**

| | |
|--|--|
| **찬성** | “괜찮은지”를 모델이 채점하면 다시 AI-on-top. 벤치·정직성 모두와 충돌. |
| **나쁜 의견 위험** | 실재함. 다만 해법은 **심판 AI**가 아니라 **외부 사실 신호 + 사람 재결정 게이트**. |

### 절제선 (권고)

1. **금지:** 의견 점수, “추천/비추천”, 자동 기각, 호스트 몰래 AI veto.  
2. **허용(최소 신호, 심판 아님):** 사람 「이 의견으로」**이후** market/reality — `이미있음` 등은 **사실에 가까운 배지**.  
3. **사람 재결정 게이트:** `이미있음`이면 다음이 **막히지 않음** — 선택지 세 개만: (계속 간다 / 의견 수정 / 막혔어·묶어줘). AI가 고르지 않음.  
4. **동료 신호(비AI):** 다른 시드 목록을 옆에 보여 “팀 의견과 겹침/충돌”은 **사람이 보게** — 랭킹 없음.  
5. **스킵:** 검증 스킵 가능하되 보고서에 **「시중 미검증」** 배지(정직).

→ “AI 최소 신호”가 필요하면 **품질 심판이 아니라 시중·현실 배지**로 충족. 인계의 “사람 책임으로 남김”에 **동의**, 단 **이미있음 무시하고 확정**은 배지로 기록해 심사·회고에 남길 것.

## 3) 사람 의견 → market/reality 재배치

### 판정: **맞다. 2228·기존 게이트와 정합. 그대로 복붙은 주의.**

| 맞음 | 주의 |
|------|------|
| 시중검색을 **선택 후 검증**에 쓰는 것이 데모 심장 | 프롬프트/스키마가 **발산 아이디어 pool** 가정 → **짧은 주제·시드 문장**용 시스템 프롬프트·예시 분리 |
| reality/verify를 “수정점”으로 쓰는 것 | **다듬기≠재작성** (위 High). verify는 생성자와 다른 모델 원칙 유지 시 주제 검증에도 유효 |
| 신규 kind 최소화(seedtopic만) | market을 의견 **확정 전**에 돌리면 사실상 AI가 선택 개입 → **확정 의사 후** 호출이 맞음 |
| | 모호한 시드(“뭔가 불편”) → 검색 노이즈·거짓 ‘이미있음’ ↑ — 사람 의견은 **한 문장 구체화** 힌트(강제 에세이 X) |
| | 여러 의견 중 하나 pick 후 market 1회 — OK. **전원 의견에 일괄 market**은 비용·지연·심판화 |

**재배치 한 줄:** market/reality의 **역할(신선도·실현 점검)**은 유지하고 **입력 대상만** ‘사람 고른 의견/주제’로 바꾼다. kind 이름·미터 purpose를 `idea`와 구분해 정직 라벨.

## 4) seedtopic=fallback only → 0145 자동종합 우려 해소?

### 판정: **구조적으로 해소. 운영·UX로 재유입 가능 — 가드레일 유지 필수.**

- **해소되는 것:** “매번 묶기”가 기본이 아니므로 0145의 **상시 종합·단일 확정 체감** 위험이 기본 경로에서 사라짐.  
- **안 사라지는 것:** fallback 호출 시의 위험 — 후보 1개·attribution 환각·이종 MoA·윤문 세탁.  
- **유지 가드레일(0145 그대로):** 후보 ≥3, 기본 선택 없음, **시드 원문 인용**, 단일 모델 1회, “여러 모델이 더 잘 묶음” 금지.  
- **추가:** fallback 사용 시 UI/보고서에 **「AI 묶기(막힘)」** 배지 — 기본 경로와 구분(정직).

→ Claude “자동종합 함정 회피”에 **조건부 동의** (fallback UX가 secondary일 때).
