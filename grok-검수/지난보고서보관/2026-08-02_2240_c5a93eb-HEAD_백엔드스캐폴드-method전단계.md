## 2. 발견 목록 (심각도순)

### [Blocker] `server/index.js` 전 엔드포인트 — 인증·인가 없음

· **문제:** 세션 생성/조회/PATCH/join/ideas/votes/AI를 아는(또는 찍는) 누구나 호출 가능. 호스트 검증·멤버 토큰·쿠키 세션 없음.  
· **재현:** `POST /api/sessions` 후 얻은 `id`로 제3자가 `PATCH`로 `phase`·`members`·`votes` 덮어쓰기, 또는 `join`에 `isHost: true` 삽입.  
· **제안:** 세션별 **host secret / participant token**(생성 시 발급, httpOnly 쿠키 또는 `Authorization`), 뮤테이션은 토큰 스코프 검사. 공개는 초대 링크로 join만 최소화.

---

### [Blocker] `server/store.js:10` — 세션 id가 UUID 앞 8자 (추측·열거 가능)

· **문제:** `randomUUID().slice(0, 8)` → 약 32bit 엔트로피. `GET /api/sessions/:id`가 존재 여부를 그대로 알려 주므로 **무인증 열거**와 잘 맞물림.  
· **재현:** 짧은 id 공간 brute-force 또는 초대 링크 유출 후 타 세션 탐색.  
· **제안:** **전체 UUID**(또는 128bit+ URL-safe). 조회도 토큰 없으면 404로 통일(존재 여부 최소화).

---

### [Blocker] `server/index.js:11` — `cors()` 기본(전체 오리진 허용)

· **문제:** 브라우저에서 임의 사이트가 API를 호출할 수 있는 설정. 지금 쿠키가 없어도, 이후 쿠키 인증을 붙이면 **CSRF/크로스사이트 남용**으로 직행. 상용 기본값으로 부적합.  
· **재현:** 악성 페이지에서 `fetch("https://api…/api/sessions", {method:"POST",…})`.  
· **제안:** `origin: [허용 프론트 URL]` 화이트리스트, `credentials` 쓸 때 `*` 금지. 프리뷰/프로덕션 분리.

---

### [Blocker] `server/index.js:78-81` + `ai.js` — `/api/ai` 남용·쿼터·비용 폭탄 가드 없음

· **문제:** 인증·rate limit·kind allowlist·토큰/길이 제한 없음. `ANTHROPIC_API_KEY`가 켜지고 TODO가 구현되는 순간 **외부에서 비용 소진** 가능. 현재도 키 있으면 health는 `configured`인데 실제는 목업 — 운영 착시.  
· **재현:** 스크립트로 `POST /api/ai` 폭주 (키 연동 후 과금).  
· **제안:** 세션 멤버만 호출, IP/세션/유저별 rate limit, `kind` enum, `context` 크기 상한, 일일 쿼터, 키 없으면 503 명확화. 키 있어도 미구현이면 `configured:false` 또는 `ai:"mock-pending"`.

---

### [High] `server/index.js:46-49` — PATCH가 `req.body` 전체 병합 (필드 화이트리스트 없음)

· **문제:** 클라이언트가 `phase`, `members`, `votes`, `goal`, 임의 키를 통째로 교체. Mongo 경로에선 **업데이트 연산자 주입**(`$set`/`$unset`/`$rename` 등) 위험 (`findByIdAndUpdate(id, patch)`).  
· **재현:** `PATCH /api/sessions/:id` body `{"$unset":{"members":true}}` 또는 `{"members":[],"votes":{}}`.  
· **제안:** allowlist(`phase`, `deadlineAt` 등) + Mongo는 항상 `{ $set: sanitized }`. `id`/`createdAt`/`host` 불변.

---

### [High] `server/index.js:52-76` — join / ideas / votes 입력 검증·신원 바인딩 부재

· **문제:**  
  - join: `member.id` 없으면 전원 동일 키로 합쳐짐; `isHost` 클라이언트 선언 가능.  
  - ideas: `req.body`가 `id`/`likes` 덮어씀.  
  - votes: `memberId`·`themeIds` 타입/개수 미검증; 타인 `memberId`로 투표 위조.  
· **재현:** join body `{ "isHost": true, "name": "악" }` / votes `{ "memberId": "sh", "themeIds": [1,2,3,4,5] }`.  
· **제안:** 서버 발급 memberId·호스트 플래그, zod/joi 스키마, 투표는 세션당·인당 상한.

---

### [High] 동시성 — get→수정→update 패턴 (memory·Mongo 공통)

· **문제:** join/ideas/votes가 `get` 후 배열/객체 만들어 `update`. 동시 요청 시 **lost update**. memory Map은 단일 프로세스에서도 원자성 없음.  
· **재현:** 두 클라이언트가 동시에 idea POST → 한쪽 아이디어 유실.  
· **제안:** Mongo `findOneAndUpdate` + `$push`/`$addToSet`, 또는 버전 필드(optimistic lock). memory도 키별 큐/뮤텍스.

---

### [High] 에러 처리·프로세스 안정성 부재 (`server/index.js`)

· **문제:** 라우트에 try/catch 없음. Mongo 일시 오류·예상 밖 throw 시 Express 기본 스택 응답 가능, 처리 누락 시 프로세스 위험. JSON 파싱 에러 커스텀 메시지 없음.  
· **제안:** async 래퍼, 통일 `{ error, code }`, 프로덕션에서 스택 비노출, `express.json({ limit: "64kb" })`.

---

### [High] XSS·콘텐츠 안전 (상용화 관점, 현재+연동 후)

· **문제:**  
  - React 텍스트 노드는 기본 이스케이프 → **저장형/반영 XSS는 현재 UI에서 낮음** (`dangerouslySetInnerHTML` 없음 — 양호).  
  - 그러나 API가 `goal`/아이디어 HTML을 그대로 저장·반환하고, 이후 PDF·이메일·관리자 HTML·Markdown 렌더를 붙이면 **stored XSS**로 전이.  
  - `ai.js` 목업이 `goal`을 문자열에 삽입해 반환 — 프론트가 HTML로 넣으면 위험.  
· **제안:** 저장 전 길이·문자 정책, 출력은 계속 text/Markdown sanitize, HTML 렌더 금지 원칙을 규칙으로 고정. Content-Security-Policy 헤더(helmet).

---

### [Medium] `server/store.js` — memory↔Mongo 추상화 함정

· **문제:**  
  1. `strict: false` 스키마 → 임의 필드 영속, 검증 책임 전무.  
  2. memory `update`는 shallow merge, Mongo `findByIdAndUpdate`는 업데이트 문서 의미 — **동일 인터페이스라도 의미 불일치**.  
  3. Mongo 실패 시 **조용히 memory 폴백** → 프로덕션에서 “저장됐다” 착각 후 재시작 시 데이터 소실.  
  4. `all()`이 노출되면(지금은 라우트 없음) 전체 세션 덤프 위험 — 인터페이스에 이미 존재.  
· **제안:** 프로덕션에서 Mongo 실패는 **프로세스 기동 실패**, 폴백 금지. 스키마/allowlist 공유. `all()` 제거 또는 관리자 전용.

---

### [Medium] 쿠키·세션 설계 공백 (아직 코드 없음 = 기회이자 리스크)

· **문제:** 쿠키 미사용은 지금은 안전하나, 상용 인증을 나중에 붙일 때 Secure/HttpOnly/SameSite=Lax|Strict, CSRF 더블서밋, 세션 고정 방지 설계가 문서·코드에 없음. 로컬스토리지 JWT만 쓰면 XSS 시 토큰 탈취.  
· **제안:** 참가 토큰은 **httpOnly + Secure + SameSite** 쿠키 우선, CORS credentials와 오리진 화이트리스트를 한 세트로 설계.
