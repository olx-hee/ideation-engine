## 2. 질문에 대한 짧은 답

| 질문 | 답 |
|------|-----|
| id 병합 중복/충돌 | 같은 마운트에서 content가 재하이드레이션되면 **낙관적 Date.now() id와 서버 id가 달라 중복** 가능. 단계 재진입(언마운트) 후엔 서버본만 남아 중복은 보통 해소. |

| XSS | `text`/`title`/`name` 텍스트 노드 — **신규 XSS 낮음**. HTML 렌더 도입 시 전이. |
| 투표 “로컬 없을 때만” | 진행 중 덮어쓰기 방지 **유효**. `ie_votes`에 키만 남은 빈 투표·전부 false 객체면 복원 스킵 가능. |
| 무인증 POST 남용 | **실표면 증가(High)**. UUID만 있으면 ice/ideas/votes 스팸·위조. AI만 레이트리밋. |

## 3. 발견 목록

### [High] `server/index.js` ice/ideas/votes — 무인증·무쿼터 POST (B1)

· **문제:** 세션 UUID만 알면 누구나 `memberId`를 위조해 ice/ideas를 무한 append, votes를 덮어쓸 수 있다. 콘텐츠 영속화로 공격 가치가 커짐. get→update는 동시 요청 시 유실(B3)도 여전.  
· **재현:** 초대 링크의 id로 `POST /api/sessions/:id/ice` 반복.  
· **제안:** B1 토큰·멤버 바인딩 전까지라도 ice/ideas/votes에 **IP/세션 rate limit**, 세션당 개수 상한. 공유 전 B1 일정 필수.

---

### [Medium] `IcePhase` / `IdeaBrainstorm` — 낙관적 id vs 서버 id 불일치 → 중복 가능

· **문제:** 로컬은 `id: Date.now()`로 넣고, POST body에 id를 안 보냄 → 서버가 **다른** `Date.now()`로 저장. 병합은 id 집합만 본다. `content`가 제출 후 다시 채워지면(재GET·엄격한 remount+이미 로컬에 낙관적 항목이 남은 채 initial* 갱신) **동일 본문 두 장**.  
· **재현:** 제출 직후 `content`가 서버 응답으로 갱신되는 경로가 생기면(또는 개발 중 강제 refetch) 로컬 X + 서버 Y 동시 표시.  
· **제안:** POST 성공 시 응답 entry로 로컬 id 교체, 또는 클라이언트 `clientId`를 서버가 에코·병합 키로 사용.

---

### [Medium] best-effort POST 실패 → 새로고침/단계 재진입 시 제출물 소실

· **문제:** UI는 성공한 듯 보이지만 서버 미저장. Ice/Idea는 step 전환 시 언마운트되어 **로컬 state도 사라짐**. 실패분을 재시도·큐잉하지 않음.  
· **재현:** 서버 중지 → ice 제출 → “제출 완료” → 다음 단계 후 다시 Phase1 또는 F5 → 내 답 없음.  
· **제안:** 실패 시 토스트/배지, `ie_pending_*` 큐, 또는 POST resolve 전엔 “동기화 중”.

---

### [Medium] `IdeaPhase` — SCAMPER / Six Hats 경로에 영속화 없음

· **문제:** `sessionId`/`initialIdeas`가 `IdeaBrainstorm`에만 전달. 방식 3종 중 2종은 서버 콘텐츠 영속 대상 밖.  
· **재현:** method=scamper로 세션 → 입력 → F5 → 서버 ideas 비어 있음.  
· **제안:** 프레임워크별 저장 스키마를 두거나, 공통 ideas로 정규화해 POST.

---

### [Medium] `IdeaBrainstorm` 하이드레이션 — 서버 ideas 작성자를 전부 `meName`으로 표시

· **문제:** `initialIdeas.map`이 `member: { name: meName, … }` 고정. 지금은 단일 유저라 괜찮지만, join 연동 시 **타인 아이디어가 내 이름으로** 보임.  
· **제안:** `e.name` / `memberId` → `getMember` 매핑 (IcePhase는 name 사용 — 더 나음).

---

### [Low] 투표 복원 엣지 — `Object.keys(votes).length === 0`만 검사

· **문제:** `ie_votes`가 `{ "1": false }`처럼 키만 있으면 “로컬 있음”으로 간주해 서버 복원 스킵. 반대로 로컬 `{}` + 서버 값이면 복원(의도).  
· **제안:** `Object.values(votes).some(Boolean)` 없을 때만 복원, 또는 “활성 투표 없음” 정의 명확화.

---

### [Low] 데모 `ICE_ANSWERS`에 `id` 없음

· **문제:** 병합 `have`가 demo 행을 추적 못 함(필터로 제외). 기능 해는 거의 없으나, 훗날 서버에 데모 시드가 섞이면 키 전략이 더 필요.  
· **제안:** 데모 상수에도 안정적 `id` (`demo-sh` 등).

---

### [Question] phaseReconciled가 첫 **정수** serverPhase에 고정

· `phase: 0`이 먼저 오면 reconciled=true가 되어, 이후 더 큰 phase가 같은 마운트에서 늦게 오는 경우는 드묾(한 번 GET). 의도와 맞는지 확인만.
