## 1. [요청①] 게이트 방법론

코드상: `reality`(DeepSeek, ①~⑤·통과/보류) → `market`(Brave 실검색 + DeepSeek 판정, `<<<데이터>>>` 격리, 도메인 다양, 세계최초 낮춤). 요청의 SKT/CLOVA 포착 사례는 **방법론적으로 올바른 스모크**.

| 요소 | 판정 |
|------|------|
| 발산 분리 + 추정→실검색 보강 | ✅ 0430 권고와 일치 |
| 검색 격리·도메인 다양·길이 상한 | ✅ 1700 안전장치 |
| 생성(Solar idea) ≠ 검증(Llama verify) | ✅ |
| reality/market 판정 모두 DeepSeek | ⚠️ **생성 대비 독립은 OK**, reality↔market은 **동일 모델** — “이중 독립 검증”으로 과장 금지 |
| Brave ≠ LLM | ✅ 도구 분업의 실체 |

**함정:**
1. **쿼리 품질** — 아이디어 문장 그대로면 잡음/광고; 쿼리 정규화 없으면 라벨 흔들림.  
2. **1콜·상위 3건** — 공백·미확인 과다 또는 유사 누락.  
3. **판정은 결국 LLM** — URL은 실측, **라벨은 해석**; 사람/심사용으로는 URL을 보여야 함.  
4. **`BRAVE_API_KEY` 없으면 빈 검색** — 전부 공백·미확인으로 미끄러질 수 있음 → health/배지에 검색 ON 표시.  
5. **백엔드만** — 제품 스토리로 쓰려면 UI 연결 전 “구현됨” 수위 제한.

**판정:** 방법론 **승인**. 완성된 제품 게이트가 아니라 **정직한 파이프 1차 구현**.

## 2. [요청②] 「적재적소 분업=정체성」정직성

| | 판정 |
|--|------|
| 벤치와 정합? | ✅ 「자동 섞기 품질승」반증 / 「kind·도구별 배분」생존 — 데이터 서사와 맞음 |
| Brave 합류 | ✅ **특화 도구 축**의 실현(Perplexity 유료 대체 방향과도 1549/1700) |
| 방어력 | ✅ “전부 Solar 한 방” 반박에 **역할표+실검색**이 유효 |

**과장·오독 위험 (반드시 막을 것):**
| 위험 문장 | 정직한 문장 |
|-----------|-------------|
| 7개 모델을 써서 더 창의 | 작업마다 **측정된 1모델·1도구** |
| Brave = 우리 LLM 우위 | Brave는 **검색 API**, 멀티LLM이 아님 |
| 한 세션에 항상 7모델 | **kind를 탄 것만** 호출; concepts 4모델은 창의 단계 때 |
| 많이 쓸수록 좋다 | **적재적소·원가**가 포인트 |

**판정:** 프레임 **채택**. “다중 LLM 플랫폼”이 아니라 **「라우팅된 모델 + 검색 도구의 역할 분업」**.

## 3. [요청③] README 핵심 메시지 · 필수 단서

**넣어도 된다** — 다만 아래를 **같은 블록에** 붙일 것.

**필수 정직성 단서:**
1. **백엔드 구현 · 프론트/데모 UI 미연결**(또는 연결 시점 명시).  
2. market 사람검증 **소표본**(요청: 2아이디어); 라벨은 LLM 판정+URL 근거.  
3. ③⑤는 **추정**, market이 **보강**(완전 대체 아님).  
4. 「자동 앙상블로 품질↑」**주장 안 함** — 적재적소만.  
5. 창의 사람축 n=6·본인1; 게이트 **후** 사람축 재측정 **미실시**.  
6. Brave/키 없으면 검색 게이트 **비활성** 가능.  
7. “7모델”은 **카탈로그·역할표**, 매 세션 동시 7콜 보장 아님.

없으면 README에 넣지 말 것.

## 4. [요청④] 「단일 래퍼냐」답변으로 충분한가

**말로만 하면 불충분. 프레임+증거면 충분에 가까움.**

심사 답변 최소 세트:
1. **한 줄:** “한 모델 랩이 아니라, 일마다 다른 모델·검색을 붙인 퍼실리테이션 파이프.”

4. **한 줄 금지:** “모델 많아서 창의적.”

더 있으면 좋은 것: 프론트에 reality/market 카드, 게이트 후 사람축 소표본.
