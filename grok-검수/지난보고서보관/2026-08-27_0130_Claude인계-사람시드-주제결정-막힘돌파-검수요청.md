## 1. 방향 정정 이력 (중요)
- 1차 시도: 프로필→"주제 확정 후 각자 실행 스텝 배분"(팀플 실행 가이드) → **사용자 지적: 우리 제품은 '주제를 정하는 회의'를 돕는 것, 실행 배분이 아님.**
- 2차: "개인특성 → 주제·방향 결정에 사용"으로 재정의 → 또 지적: **"AI가 바로 주제 뱉지 말고, 사람이 먼저 회의·시드 내면 그걸 기반으로 AI가 묶어야."**
- **확정 철학: 사람이 먼저(회의·시드) → AI는 그걸 묶고 도와주는 역할. AI가 무에서 주제 만들지 않음.**

## 2. 확정 설계 (2안, 둘 다 '주제/방향 결정'용)
**A) 회의 시작 — 사람 시드 → AI가 주제화**
- 팀원들이 각자 **시드(관찰·불편·관심)**를 먼저 입력. **시드가 다 차야 AI 버튼 활성**(human-first 게이트).
- AI가 그 시드들을 **묶어** 주제 후보 3개 + 각 **"근거 시드(누구의 어떤 시드에서)"** 표기 → 팀이 선택.
- 실데이터 예: 지훈"배달만 시켜먹고 만족 못함"+서연"집 오는 순간 허함" → **"퇴근 직후 허기·허전함 동시 케어 저녁 루틴"** (근거 시드 명시). 3안 모두 시드 attribution 있음.

**B) 회의 중 막힘 — 지금까지 논의 + 본인 역량 → 돌파 방향**
- "AI에게 물어보기" → **그 순간까지의 논의 맥락 + 이 사람 역량**으로 돌파 방향 2개.
- 실데이터 예: 막힘="AI 안부전화 이미 SKT·CLOVA가 함(시중검색이 잡음), 차별점 못 찾음" → 디자이너 강점으로 "인터뷰 기반 정서적 동행 UX 재설계 / '정시' 경험 재정의". **← 시중검색 게이트가 '이미있음' 잡아 막혔을 때와 자연 연결.**

## 3. Grok에게 (검수 질문)

2. **A의 "AI가 시드 묶기"**가 우리가 반증한 '자동 종합(앙상블)'과 뭐가 다른가? (여기선 사람 시드가 입력이고 사람이 최종 선택 → 괜찮은가, 아니면 또 "AI가 합쳐줌" 함정인가?)
