## 0. 요약 판정

A~B의 정직 프레임(**분업 = 난이도 라우팅 + 비용 + 다양성 + 폭넓은 검증 / 품질우위·각도특화 아님**)은 원자료와 **대체로 정합하며 승인**한다.  
다만 **무거운 analyze 「추론 뒤집힘」은 사실상 단일심판**이므로 발표는 **잠정·재검증 전제**로만 — 「실증 완료」단정은 Medium 과대.

### 1-2. 정직 프레임 승인 조건

**승인:** 「품질우위·각도특화 아님 / 난이도 라우팅·비용·다양성·탐색 폭」.

**수위 조절 (무거운 추론 뒤집힘):**

| 말 | 허용? |
|----|-------|
| 「가벼운 발산에선 추론이 약했고, 무거운 분석 탐색에선 추론형이 상단에 많이 보였다」 | ✅ |
| 「난이도별 라우팅 **가설이 실측으로 뒷받침되는 방향** (재검증 전)」 | ✅ |
| 「추론 뒤집힘 **실증 완료** / flagship=Nemotron **확정**」 | ❌ Medium 과대 — 문서 본인도 단일심판 고지 |

**High (정직성 충돌 — 코드↔벤치):**  
heavy는 **추론 ON·max_tokens 크게**로 측정했는데, 현 adapter는 `tier===flagship`이면 **`reasoning: { enabled: false }`**.  
지금 GLM을 Nemotron으로 바꿔도 **벤치 조건과 다른 설정**이면 「실측 반영」이 거짓에 가깝다.  
→ flagship 교체 시 **(i) heavy와 같이 reasoning ON** 또는 **(ii) reasoning OFF로 재벤치 후 선정** 중 하나를 **반드시** 고를 것.

## 2. [E-2] 도입 결정 검수

### 2-1. Map-Reduce — 🟢 도입 → **승인 (얇게)**

| 축 | 평가 |
|----|------|
| 사업성 | 통제실험의 「나눌수록↓」를 정면 대응 — 품질 스토리 회복 가능성 |
| 정직성 | 종합 콜은 **추가 비용**. 미터에 `purpose: synthesize`(또는 repair)로 분리, 절감% 분모 규칙 §5 준수 |
| §9 과설계 | fanout 끝에 **종합 1콜** 정도면 OK. 분류기·캐스케이드·별 오케스트레이터 프레임워크까지 가면 과함 |
| 리스크 | **미실험**. 도입=가설 구현 → 작은 A/B(종합 있음/없음) 없으면 발표에서 「해결됨」금지 |

**권고:** 도입하되 슬라이스는 `orchestrate` fanout → `synthesize` 1회, 스키마/길이 제한, 골든 1세트로 회귀.

### 2-2. Langfuse — 🟢 도입 → **조건부 승인**

| 축 | 평가 |
|----|------|
| 미터 정직화 | usage/cost를 트레이스로 모으면 `estimate-mock` 탈출에 **도움** — 단 Langfuse≠자동으로 UI `measured`가 됨. **meter.js가 OpenRouter `usage.cost`를 쓰게** 하는 것이 본체, Langfuse는 관측층 |
| 검증툴 | Scores/A/B 대시보드는 원계획에 맞음. 「완성」은 **사람/다중심판 없이도 완성이라 과장** |
| §8 프라이버시 | **충돌 가능.** 아이디어 원문이 OpenRouter에 더해 **Langfuse(클라우드면 제3자)**로 분기. 학교·해커톤: 자가호스팅 또는 마스킹·옵트인·보관기간 고지. 「도입해도 프라이버시 문제 없음」은 틀림 |
| §9 | 공식 SDK로 thin wrapper면 OK. 평가 플랫폼 전체 재구축은 과설계 |

**권고:** 도입 순서는 **(1) meter에 provider cost 연결 → (2) Langfuse 트레이스**. 프라이버시 문구·환경(cloud/self-host)을 README/설계에 한 줄.

### 2-3. LiteLLM — 🟡 보류 → **승인**

OpenRouter가 이미 게이트웨이·폴백·다모델. registry+adapter가 라우팅. **지금 추가는 중복·§9 위반 소지.** 다베이스URL·직접 NIM/Anthropic 병행이 커질 때 재검토.

## 3. [E-3] 남은 문제 우선순위 (C의 5개)

### 발표 직전 (심사·데모 슬라이드)

| 순위 | 항목 | 이유 |
|------|------|------|
| **1** | **미터 정직화** (`estimate-mock`→실측 cost/배지) | 절감%가 킬러 슬라이드인데 목업 단가면 §5 정면 위반 |
| **2** | **무거운 결론 수위** (재검증 또는 「잠정·단일심판」고지) | 「뒤집힘 실증」과대 차단. 재검증 못 하면 **말만 낮춤** |
| **3** | **registry flagship 교체** + reasoning 정책 정렬 | GLM 92s는 UX 사고. High(§1-2) 해소 |
| **4** | Map-Reduce | 스토리 보강용. 없어도 「품질우위 안 함」프레임은 유지 가능 |
| **5** | B1·쿼터 | 로컬 데모만이면 발표 직후. **키 켠 채 외부 공유면 1~2와 동급으로 끌어올림** |

### 실사용·배포 전

| 순위 | 항목 |
|------|------|
| **1** | B1·일일쿼터·세션 바인딩 (비용 공격) |
| **2** | 미터 실측 + 에러/주입 가드 |
| **3** | flagship 모델·reasoning 정렬 |
| **4** | 무거운 다중심판 재검증 |
| **5** | Map-Reduce + Langfuse(고지 포함) |

**조율 vs 심판재검증 vs 미터 vs registry vs B1 — 한 줄:**  
발표 정직성 = **미터 > 무거운 말수위/재검증 ≥ registry**. 제품 안전 = **B1 ≥ 미터**. Map-Reduce는 품질 UX 개선이지 정직성 Blocker는 아님.

## 4. [E-4] 놓친 것 · 하면 안 되는 과장 라인

### 놓친 구멍

1. **flagship reasoning OFF vs heavy reasoning ON** (High) — 위 §1-2.  
2. **「40+모델」** — 실험 합산·중복 모델 가능. 발표는 실험별 수 또는 「고유 슬러그 N」으로.  
3. **Map-Reduce 비용**이 2.7× 절감을 잠식할 수 있음 — 도입 후 재측정 필수.  
4. **다양성 = 어휘 자카드만** — 의미 다양성·중복 아이디어 미측정.  
5. **ANGLE Solar-Pro-3 + 「특화」주석** — 최신 결론(특화 노이즈·Pro4)과 문서/코드 드리프트.  
6. **Langfuse를 미터 대체로 오해** — UI 배지는 앱 meter가 SoT.  
7. ice 성공 모델과 idea fanout 모델 풀이 혼재 — 「난이도 라우팅」과 「다양성 분산」을 슬라이드에서 섞지 말 것.

### 발표에서 하면 안 되는 라인

- 「분업이 단일보다 **품질이 좋다**」  
- 「각도별 **특화 모델**을 썼다」(24모델에서 재현 실패)  
- 「추론 뒤집힘으로 난이도 라우팅이 **완전히 증명**됐다」(단일심판)  
- 「Langfuse 도입으로 **검증이 끝났다**」  
- 「비용 절감 Z%」를 **추정 단가**로 보여주며 **실측인 척**  
- 「키는 서버에만」만 강조하고 **무인증 `/api/ai` 남용**을 숨김  
- Map-Reduce를 **이미 벤치로 검증된 해법**처럼 소개  

### Question

flagship을 Solar(비추론·저가·양 작업 강함)로 갈지 Nemotron(추론·빠른 5.0)으로 갈지 — **reasoning 정책과 UX(지연)**를 먼저 정한 뒤 고를 것. Solar는 「뒤집힘=추론 필수」서사와 덜 맞고, Nemotron은 추론 ON 정렬이 필요.

## 5. 보안 한 줄 (C-5)

실키 + 무인증 AI는 **배포·공유 전 B1/쿼터 필수**. Map-Reduce·Langfuse는 호출 수·로그 표면을 늘리므로 쿼터·고지와 같이 갈 것.

## 6. 한 줄 결론

**정직 프레임은 맞고, 무거운 추론 뒤집힘은 잠정만 말하라. Map-Reduce·Langfuse(조건부)·LiteLLM 보류는 대체로 타당하다. 지금 당장 뚫린 정직성 구멍은 미터 목업과 flagship 벤치조건(reasoning) 불일치다.**
