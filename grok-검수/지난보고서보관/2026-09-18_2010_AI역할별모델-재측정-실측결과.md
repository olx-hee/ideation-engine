## 0. 판정 한 줄

**재측정한 4개 작업 모두 "지금 표와 다른 답"이 나왔다.** 그런데 가장 큰 발견은 모델이 아니다 —
**`response_format`(JSON 강제)을 켜는 것이 모델을 바꾸는 것보다 효과가 컸다**(Solar 스키마 55%→100%).
그리고 **추론형 모델(GLM·Kimi·Nemotron)은 이 제품 구조에 맞지 않는다**는 게 반복 확인됐다.

**보안:** 이번 측정은 로컬 벤치 — 신규 공격면 없음. 키는 `.env`(서버 전용)에서만 읽었고 값은 출력하지 않았다.
다만 **프롬프트 주입(검색 결과 → LLM)은 이번에도 미측정**으로 남았다(§7).

## 1. 무엇을 어떻게 쟀는가

기존 벤치는 **품질 점수 + 비용**만 쟀다. 새 작업표(`docs/05`)는 여기에 세 축을 요구하므로, **심판 LLM 없이 자동 판정**되는 지표를 새로 만들었다.

| 새 축 | 자동 판정 방법 |
|-------|----------------|
| 지연 | 호출 왕복 시간의 p50 / p95 (비스트리밍) |
| 스키마 | JSON 파싱 + 필수 필드·값 범위 검사 (화면이 그리는 실제 필드 기준) |
| 근거 충실도 | 출력 URL ⊄ 제공 링크 = **URL 환각** / `exists` 요약의 수치가 스니펫에 없으면 **숫자 환각** / 스니펫 방향(있다·없다)을 뒤집으면 **근거 역방향** |
| 판단 타당성 | 정답이 정해진 케이스로 채점 (빈약한 답 → 꼬리질문 / 포화 시장 → `fix`·`re`) |
| 일관성 | 같은 입력 반복 시 같은 등급·같은 추천이 나오는 비율 |

스키마 검사는 목업의 실제 필드(`mock.js`)를 그대로 썼다 — `grade: go|fix|re`, `exists/feasibility/missingSkills/need/timeline/comments`, `parts[].effort` 등.

## 2. 결과 ① 실시간 2작업 (#1 꼬리질문 · #3 뜻풀이)

`newaxis-latency.mjs`(v1) → `newaxis-latency2.mjs`(v2). **v2는 v1에서 딱 두 가지만 바꿨다**: (a) 충분함 기준을 프롬프트에 명시, (b) `response_format: json_object` 강제.

| 모델 | 스키마 v1→v2 | 꼬리질문 정확 v1→v2 | p50 | **p95** | $/콜 |
|------|--------------|---------------------|-----|---------|------|
| Gemini-2.5-Flash | 100 → 100 | 50 → **100** | 1101ms | **1432ms** | 0.000161 |
| Mistral-Medium-3 | 100 → 100 | 50 → **100** | 1085ms | 1792ms | 0.000136 |
| GPT-4o-mini | 100 → 100 | 50 → **100** | 1324ms | 2271ms | 0.000053 |
| **Flash-Lite** | 100 → 100 | 50 → **100** | **906ms** | 2573ms | **0.0000326** |
| Llama-3.3 | **55 → 100** | 50 → **100** | 1923ms | 8709ms | 0.000068 |
| **Solar-Pro4** | **55 → 100** | 50 → **100** | 879ms | **11279ms** | 0.0000315 |
| Nemotron-3.5L | 20 → 80 | 50 → 67 | 1655ms | 6140ms | 0.0000467 |

**[High] 현행 표의 Solar는 실시간에 쓸 수 없다.** p50은 0.88초로 가장 빠른데 **p95가 11.3초**다. v1에서도 9.1초로 같은 꼬리가 나왔으니 우연이 아니다. 인터뷰 중 20번에 1번 11초를 기다리게 하는 셈이다.

**[High] 꼬리질문 판단 50%는 모델 잘못이 아니었다.** v1에서 **전 모델이** 자세한 답에도 "더 물어보자"로 답했다(`enough=false`). 기준을 안 줬기 때문이고, 기준 3줄을 넣으니 **전부 100%**가 됐다. `docs/05` #1의 폴백("꼬리질문 없이 다음 질문")은 기준 없이는 **영원히 발동하지 않는다.**

**[High] `response_format`이 모델 교체보다 효과적이다.** Solar·Llama가 **55% → 100%**. 진단(`newaxis-diag.mjs`)에서 Solar는 JSON 지시를 무시하고 산문으로 답하고 있었다.

## 4. 결과 ③ #11 파트 나누기 · #13 추천 + 근거 한 줄

**[High] `docs/05`가 "중간"이라 적어둔 #11은 가장 싼 모델로 충분하다.** Flash-Lite가 스키마·난이도 커버·후보 유효성·없는 스킬 대안 **전부 100%**에 p95 3.9초, 콜당 $0.000125다. 이름 누출도 0건이었다(P번호만 사용). **이것이 "비용 절감"의 실측 근거**다.

**[정정] 추천이 흔들린다는 제 우려는 틀렸다.** 동점 케이스를 6회 반복했더니 **네 모델 모두 추천 안정성 100%**(P4를 6/6). 같은 입력에 추천이 바뀌는 문제는 **없다**.

→ 따라서 사용자가 결정한 "**추천 + 근거 한 줄**"은 그대로 가도 된다. 단 **"우열을 가리기 어려우면 팀장에게"는 모델에 맡기면 작동하지 않는다.** 스킬 매칭 점수 차이가 작으면 **코드가 tie로 강제**해야 한다.

## 7. 한계 — 이 숫자로 말하면 안 되는 것

1. **표본이 작다.** 실시간 15콜/모델, #7 9콜/모델, #15 4콜/모델. p95는 사실상 **최악값**이다. 방향 판단용이며 "Gemini가 Mistral보다 360ms 빠르다"처럼 읽으면 안 된다.
2. **검색 스니펫은 합성**이다. Brave 실연동이 아니고, 스니펫이 짧고 단정적이다. **실제 검색 결과는 길고 모순되므로 환각률은 올라갈 수 있다.** 환각 0%를 "환각 없음"으로 발표하면 정직성 위반.
3. **#2 최근 소식 카드는 측정하지 않았다.** Brave 키가 있으니 붙인 뒤 별도 측정.
4. **프롬프트 주입 미측정.** 악의적 웹페이지가 "이전 지시를 무시하라"를 심는 경우를 테스트하지 않았다. §0 보안 항목과 함께 **설계 단계에서 데이터 구획 분리 + 도메인 화이트리스트**로 막아야 한다.
5. **추론 OFF 설정을 안 켜고 쟀다.** `registry.js` 주석대로 GLM을 추론 OFF로 돌리면 결과가 달라질 수 있다. "GLM이 나쁘다"가 아니라 **"기본 설정 + JSON 강제 + 토큰 상한 조합에서 빈 응답"**이 정확한 서술이다.
6. **내용 품질은 이번에 안 쟀다.** #11의 파트 나눔이 *타당한가*, #7 등급이 *맞는가*는 사람이 봐야 한다 → **골든 세션 1~2개**가 남은 숙제.
7. **지연에 네트워크·OpenRouter 라우팅 변동이 포함**된다. 한국 리전 직결이 아니므로 실제 배포 지연은 달라진다.
