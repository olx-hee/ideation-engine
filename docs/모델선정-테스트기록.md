## 0. 이번 커밋에 바뀐 것

역할 배분(role map)을 실제 코드로 반영했습니다.

| 파일 | 변경 |
|------|------|
| `server/orchestrator/registry.js` | role map 확정: `report → DeepSeek-V3.2`(Solar에서 교체), `verify`(독립 검증) 신설, `CONCEPT_LENSES`(컨셉 4렌즈=4모델) 추가 |

## 0-2. 2026-09-18 재측정 — AI 작업이 15개로 늘어난 뒤 (쉬운 말 정리 · 코드 미반영)

백엔드 핸드오프 문서(`IdeationEngine-개발핸드오프/docs/05-AI-작업-목록.md`)에서 AI가 할 일이 **15개**로 정해졌습니다.
지금까지는 작업 4~5종(키워드·아이스·발산·분석·보고)만 기준으로 모델을 골랐는데, 새로 생긴 작업(인터뷰 꼬리질문·뜻풀이·파트 나누기·후보 추천 등)은
그 표로는 안 맞을 수 있어서 **실제로 모델들을 다시 불러서** 쟀습니다. (OpenRouter 실호출 약 370번, 총비용 0.3달러 미만)

**가장 큰 발견은 모델이 아니었습니다.** 응답을 "JSON 형식으로만 달라"고 **강제하는 설정**을 켜는 것이, 모델을 바꾸는 것보다 효과가 컸습니다.
Solar-Pro4는 이 설정 없이는 화면이 못 읽는 형태(줄글)로 답할 때가 45%나 됐는데, 설정을 켜자 0%가 됐습니다.

그 밖에 알게 된 것:

- **실시간으로 답해야 하는 작업 2개**(인터뷰 꼬리질문 판단, "이게 뭐예요?" 뜻풀이)는 사람이 화면 앞에서 기다리는 유일한 작업입니다.
  지금 표의 Solar-Pro4는 평소엔 빠르지만(0.9초) **스무 번에 한 번쯤 11초**가 걸려서 실시간에는 못 씁니다. 이 둘은 품질보다 **속도**로 골라야 합니다.
- **AI 검증·현실성**에서 걱정했던 "검색 결과에 없는 걸 지어내지 않을까"는, 형식을 강제하고 "검색 결과에 없는 건 쓰지 마라"를 프롬프트에 넣으니 **환각이 0건**이었습니다.
  (단, 이번 검색 결과는 실제 Brave가 아니라 짧게 만든 예시라서, 진짜 검색 결과로는 다시 확인이 필요합니다.)
- **파트 나누기·겹친 후보 추천**은 문서가 "중간" 등급 모델을 추천했지만, 실제로는 **가장 싼 모델**로도 100% 통과했습니다.
- **보고서(A4 2쪽)**는 모델을 바꿔도 다들 짧게 씁니다 — 이건 모델 문제가 아니라 "이만큼 써라"를 프롬프트에 못 박아야 하는 문제입니다.
- **GLM-4.6·Kimi-K2.5·Nemotron**은 셋 다 "깊이 생각하는" 방식의 모델이라, JSON 형식 강제 + 짧은 답 제한과 궁합이 안 맞아 응답이 자주 비었습니다. 이 셋은 후보에서 뺐습니다.

## 0-3. 2026-09-19 재측정 — 나머지 8개 작업(#2,#4,#5,#6,#8,#9,#10,#12) 실측 (쉬운 말 정리 · 코드 미반영)

0-2에서는 15개 작업 중 6개(#1,#3,#7,#11,#13,#15)만 새로 쟀습니다. 나머지 8개는 옛 4~5종 role map에
얹혀서 **한 번도 직접 실측된 적이 없었습니다.** 이번에 그 8개 중 7개를 채웠습니다(#14는 AI가 아니라
계산이라 대상 아님). OpenRouter 실호출 약 120번, 총비용 0.03달러 미만.
실행 스크립트: `benchmarks/newaxis-flow.mjs`(6작업) · `newaxis-news.mjs`(#2) · `newaxis-aggregate.mjs`(#8).

**모델 후보:** Flash-Lite · Gemini-2.5-Flash · Solar-Pro4 · DeepSeek-V3.2 · Llama-3.3 · Mistral-Medium-3
(GLM-4.6·Kimi-K2.5·Nemotron은 0-2에서 스키마 0%·응답 지연 등으로 이미 탈락해 이번엔 제외).

### 잘 된 것 — 모델을 거의 안 가리는 작업 (아무거나 싼 거 써도 됨)

- **#6 아이디어 추천, #9 숨은 공통점:** 6개 모델 전부 스키마·정확도 100%. 가장 싼 Flash-Lite도 가장
  비싼 모델과 똑같이 잘함 → **Flash-Lite로 충분**(문서가 "중간"으로 표시했던 것보다 낮은 등급도 가능).
- **#2 최근 소식 카드:** 6개 모델 전부 URL 환각 0%·숫자 환각 0%·카테고리(시장/기술/규제) 커버 100%.
  "검색 결과에 없는 건 쓰지 마라"를 프롬프트에 넣고 JSON을 강제하면, 이 작업도 모델을 안 가립니다.
  다만 **지연 차이가 큽니다** — Flash-Lite 1.9초 vs Llama-3.3 23.1초(p95). 세션 시작 직후 "미리" 부르는
  작업이라 급하진 않지만, 그래도 굳이 느리고 비싼 모델을 쓸 이유가 없어 **Flash-Lite 추천**.

### 걸린 것 — 모델을 가리거나, 문서 기준을 다시 봐야 하는 작업

- **#4 재료 뽑기 — 개인식별정보(PII) 표시(avoid) 정확도가 모델마다 크게 다름:**
  이름·학교·학과가 담긴 문장을 "avoid: true"로 정확히 표시한 모델은 **Gemini-2.5-Flash·Mistral-Medium-3
  뿐(100%)**. **지금 가벼운 작업 기본값인 Flash-Lite는 avoidHit 0% — 한 번도 못 잡았습니다.**
  DeepSeek-V3.2도 0%. 이건 비용 문제가 아니라 **안전 문제**입니다 — #4는 원문(개인 인터뷰 답 전체)을
  그대로 AI에 보내는 유일한 작업이라, 여기서 놓치면 개인정보가 재료 목록에 그대로 남습니다.
  **제안:** ① #4는 Flash-Lite 대신 Gemini-2.5-Flash 또는 Mistral-Medium-3로 격상하거나,
  ② (더 안전) 이름·학번 등 패턴은 정규식으로 먼저 걸러내는 **코드 기반 사전 필터**를 AI 판단 앞에 두고,
  AI의 avoid 판단은 보조 수단으로만 쓴다. (①만으론 100%를 담보 못 하므로 ②를 권장.)
- **#5 재료 묶기 — 스키마 준수율이 모델마다 갈림:** 클러스터링 자체(순도·커버리지)는 스키마를 통과한
  경우 전부 100%로 잘하는데, **Gemini-2.5-Flash·Llama-3.3은 스키마 자체를 절반만 통과**(그룹 개수를
  3~5 범위 밖으로 내거나 모양이 틀림). Flash-Lite·Solar-Pro4·DeepSeek-V3.2·Mistral-Medium-3는 100%.
  **제안:** #5는 스키마가 안정적인 네 모델(특히 Flash-Lite, 비용 최저) 중 하나로.
- **#10 인사이트 카드 — 측정 방법 자체의 오탐을 발견:** "목록 형태로 쓰지 마라"를 검사하려고 만든
  체크(문장이 숫자로 시작하면 목록으로 간주)가, 정상 문장인 **"1위 아이디어는..."을 숫자 "1"로 시작한다는
  이유로 오탐**했습니다. 원문을 직접 확인하면 6개 모델 전부 정상적으로 한 문단짜리 문장을 썼습니다 —
  **실제 목록화 문제는 없음.** (검사 로직의 한계이지 모델의 결함이 아님 — 정직하게 남겨둠.)
- **#12 겹친 질문 — "예시가 주제와 관련 있나" 체크가 낱말 일치 기준이라 과소평가됨:** 형식(선택 4개+
  서술+예시)은 6개 모델 전부 100% 지켰지만, "예시 그라운딩"(예시 문장에 주제 낱말이 그대로 들어있는지)
  점수는 Gemini-2.5-Flash 0%·나머지도 50% 안팎으로 낮게 나왔습니다. 예시를 직접 읽어보면 대부분
  **의미상으론 주제와 관련 있는데 다른 낱말을 써서** 낱말-일치 검사에 걸린 경우가 많았습니다(예:
  "소분·정기배송" 대신 "공동 구매·조리 키트"처럼 관련 개념을 다른 말로 표현). **이 지표는 하한선으로만
  참고** — 사람이 몇 개를 직접 읽어보고 확인이 필요합니다.

### 방향 결정 — #8 "AI가 모은 아이디어"는 종합이 아니라 '제약'이 답이었다

0-2 이전부터 걱정했던 지점입니다 — #8은 정의상 "여러 사람 아이디어를 AI가 합치는" 작업이라, 예전에
반증됐던 "여러 AI/아이디어를 자동으로 섞으면 더 창의적"의 함정에 그대로 빠질 위험이 가장 큰 자리입니다.
그래서 모델 비교가 아니라 **프롬프트 전략 비교**를 했습니다.

- **전략 A(제약 없음):** "좋은 점을 살려서 새 아이디어를 만들어라"만 지시.
- **전략 B(제약):** 서로 다른 소스 2개 이상 인용 + 아쉬운 점 중 1개 이상을 구체적으로 어떻게
  줄였는지 설명 + 원본에 없던 실행 방법(누가·언제·어떻게) 1개 이상 추가를 **강제**.

**결과:** "아쉬운 점을 실제로 해결했나" 통과율이 평균 **37.5% → 58.25%로 올랐습니다.** 가장 크게 바뀐
모델은 **Solar-Pro4로, 0% → 100%** — 제약을 주니 "구독료 부담을 줄이려고 나눔 게시판에서 재료를
인증하면 다음 달 구독료를 할인해주는 크레딧 제도"처럼 **원본에 없던 구체적 장치**를 만들어냈습니다.
다만 DeepSeek·Gemini는 제약을 줘도 33%에 머물러 **모델에 따라 효과 차이가 큽니다.**

**결정:** #8은 **Solar-Pro4 + 전략 B(제약 프롬프트)**로 갑니다. 단, 이번 실험은 시나리오 1개·3회
반복이라 표본이 작습니다 — 그리고 제약을 줘도 100%가 안 나온 모델이 있었으므로, **서버에서
sourceIds가 실제로 2개 이상인지·improvement가 인용한 소스의 concern 낱말을 언급하는지를 코드로
한 번 더 검증하고, 실패하면 그 아이디어는 만들지 않는(문서의 "실패하면: 만들지 않음") 규칙을
그대로 지키는 것**을 권장합니다. AI 판단만으론 100%를 담보 못 합니다.

## 1. 최종 선택 — 작업별 모델 (role map, 지금 코드에 반영된 것)

| 작업(상황) | 채택 모델 | 성격 | 근거 |
|---|---|---|---|
| 키워드·아이스브레이킹 | **Gemini-2.5-Flash-Lite** | 가벼움(Light) | 짧은 작업 최고 가성비 |
| 아이디어 발산 | **단일 Solar** (품질옵션 = Self-Refine) | 창의 | 단일이 다양성 우위, 여러 번 돌리면 품질↑ |
| 컨셉 종합 | **4모델×4렌즈** (Solar·Gemini·Kimi·Mistral) | 창의(다중) | 다중이 후보 다양성↑ + 사람이 선택 |
| 분석·그룹화 | **Solar-Pro4** | 정리 | analyze 벤치 1위 + 최저가 |
| 보고·로드맵 | **DeepSeek-V3.2** | 정리 | report 벤치 1위(다른 모델) |
| 검증·팩트체크 | **Llama-3.3** (생성자와 독립) | 정답형 | 독립 검증이 자기검증보다 결함 더 잡음 |

**한 줄 원칙:** *객관·정리 작업은 작업별 최적 단일로, 창의 작업은 여러 모델 후보 → 사람 선택, 검증은 만든 모델과 다른 모델로.*

## 2. 우리가 한 테스트들 (전체 기록, 시간순)

각 테스트는 **여러 모델을 블라인드로 대결**시키고 **AI 심판(여러 개) 또는 객관 지표(Vendi·recall)로 채점**했습니다.

### ① 가벼운 작업 (키워드·아이스) — 어느 저가 모델?
- **테스트:** 여러 소형 모델로 짧은 발산·키워드.
- **결과:** **Gemini-2.5-Flash-Lite**가 한국어 안정·품질·최저가 균형 1위. 추론모델은 짧은 작업엔 오히려 꼴찌(예산을 추론에 소모).
- **결정:** 키워드·아이스 = Flash-Lite.

### ② 무거운 작업: 분석(analyze) — 추론모델이 유리할까?
- **테스트:** 8종(추론4+강범용4)이 같은 아이디어 묶음을 테마화. 심판 3, 블라인드.
- **결과:** **Solar 4.43 (1위) + 최저가.** Kimi 4.3, Grok 4.17, Nemotron 4.07, GLM 3.9, DeepSeek 3.8, Gemini 3.67, Qwen 2.5.
- **교훈:** "추론모델이 무거운 작업 유리" 가설은 **무너짐**(추론모델이 하위권). → 분석 = Solar.

### ③ 보고서(report) — 분석과 같이 취급해도 되나?
- **테스트:** 같은 8종이 더 무거운 "종합·로드맵" 작성. 심판 3.
- **결과:** **DeepSeek 4.57 (1위)**, Solar 4.53(근소 2위·4배 쌈), Kimi 4.5.
- **교훈:** 더 무거운 종합에선 추론형(DeepSeek)이 근소 1위. → **report = DeepSeek** (진짜 다른 모델로 분업).

### ④ 아이디어 생성: 단일 vs 다중 (가장 오래 헤맴 — 결론 두 번 뒤집힘)
- **처음:** 4관점을 여러 모델에 나눠 생성 → 합치기(앙상블)가 더 좋아 보였음.
- **교란 제거:** 그 "승리"는 baseline이 약한 모델이었던 착시. 공정하게 하니 **단일 Solar가 앙상블을 이기고 11~18배 쌌음.** (약한 모델 섞으면 "품질 희석")
- **재대결:** 같은 강모델을 **여러 번**(Self-Refine: 초안→비평→수정)이 단일 1회를 이김(4.53 vs 3.97). "다른 모델 섞기"(이종)는 여전히 짐.
- **다양성 재측정(Vendi):** 단일 Solar **6.06** > 다중 4.90 → **단일이 더 다양**(그냥 섞으면 뻔한 아이디어로 수렴).
- **강제 분산(steelman):** 렌즈를 강제로 벌리면 다중이 단일과 **대등**(5.05≈5.03)까지.
- **결정:** 발산 기본 = **단일 Solar**, 품질옵션 = **Self-Refine**. "자동으로 섞어 더 좋다"는 **반증됨.**

### ⑤ 컨셉 종합: 단일 vs 다중 — 다중이 사는 곳
- **테스트:** 같은 아이디어 풀·4렌즈로 단일(Solar×4렌즈) vs 다중(4모델×4렌즈) 컨셉 생성 → Vendi 다양성.
- **결과:** **다중 2.79 > 단일 2.68** (6골 중 5골 다중 우위). 비용 85배지만 **세션당 1회 4개뿐이라 절대액 무의미**($0.0085).
- **결정:** **컨셉 = 다중(4모델×4렌즈)** — 여기가 "여러 LLM"이 정직하게 값하는 자리.

### ⑥ 검증(verify) — 어느 모델이 결함을 잘 잡나 + 독립성
- **테스트 1:** 오류·환각을 심은 결과물 → 어느 모델이 잘 잡나(recall). **Solar 100%·최저가** 등 상위권 다 98~100%(포화). GLM만 30~64%(빈응답 불안정).
- **테스트 2 (핵심):** Solar가 만든 결과물을 **Solar-self vs Llama/DeepSeek-other**가 검증 → **독립 모델이 자기검증이 놓친 유효 결함을 더 잡음**(Llama 2.0 vs 1.3 / DeepSeek 2.8 vs 2.5).
- **결정:** 검증 = **생성자와 독립 모델(Llama)**. "Solar가 검증도 잘해서"가 아니라 **자기가 만든 걸 자기가 검증하면 맹점을 못 본다**는 방법론.

### ⑦ 상위(플래그십) 모델 대비 — "저렴하지만 좋다" 객관 입증
- **지적:** 지금까지 중·저가끼리만 비교 → 상위 모델 대비 객관성 부족.
- **테스트:** 우리 저가 픽 vs 플래그십 6종(Claude-Opus·GPT-5.6·Gemini-Pro·Grok-4.6·DeepSeek-V4-Pro·Qwen-max)이 분석·보고 대결. 심판 3, 블라인드.
- **결과:**

| 순위 | 모델 | 티어 | 품질 | Solar 대비 비용 |
|---|---|---|---|---|
| 1 | **DeepSeek-V3.2** | **우리** | **4.40** | 4배 |
| 2 | Claude-Opus-4.1 | 최고가 | 4.21 | **671배** |
| 3 | GPT-5.6-terra / Grok-4.6 | 상위 | 4.08 | 505 / 103배 |
| 5 | **Solar-Pro4** | **우리(최저가)** | **4.03** | 1배 |
| 6~8 | DeepSeek-V4-Pro / Gemini-Pro / Qwen-max | 상위 | 3.81 / 3.33 / 2.06 | 55~141배 |

- **교훈:** **우리 저가 픽이 671배 비싼 Claude-Opus를 이기거나 대등.** Gemini-Pro·Qwen-max는 오히려 우리 Solar보다 낮음. → **"저렴하지만 좋다"가 상위 모델 대비 강하게 성립**(정리 작업 한정).

### ⑧ 창의 "사람 눈" 축 (진행 중)
- LLM 심판은 참신함보다 다듬어진 완성도를 좋아함(편향). 그래서 창의는 **사람 블라인드 채점**으로.
- 지금까지: 사람이 다중 후보를 **4:2**로 선호(단, **n=1·약함**). → **창의 사람축 강화는 다음 과제**(발산에서 다중을 쓸지 최종 결정).

## 3. 핵심 패턴 3가지

1. **객관·정리 작업은 저가 강모델(Solar/DeepSeek)이 지배** — 뭘 재도 대부분 Solar가 최고+최저가, 보고만 DeepSeek. 상위 플래그십도 못 이김.
2. **다중 LLM의 정직한 자리는 딱 2곳** — (a) **창의 후보 생성**(여러 모델 후보 → 사람 선택) (b) **검증 독립**(생성≠검증). "같은 작업 자동 섞어 품질 우위"는 반증됨.
3. **난이도 라우팅으로 비용 절감** — 가벼움(Flash-Lite)/무거움(Solar) 2단으로 비용 크게↓. 플래그십 대비 100~671배 쌈.

---

## 4. 정직한 한계 (과장 금지)

- 대부분 **LLM 심판·객관 지표** 기반. **사람 평가는 n=1(본인)**이라 창의 판정은 잠정.
- 점수가 천장(3.8~4.6)에 몰려 상위 모델 간 차가 작음. 검증은 거의 포화.
- 표본 n=4~10, **한국어 아이디어 발산·정리** 과제에 한정 — 다른 유형(코드·수학 등)엔 다를 수 있음.
- 발산에서 다중을 최종 채택할지는 **창의 사람축 강화 후 확정.**
