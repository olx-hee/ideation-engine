# LLM 모델 선정 — 테스트 기록 & 최종 선택 (팀원용)

> "작업마다 어떤 LLM을 쓰기로 했고, 왜 그렇게 정했나"를 실측으로 정리한 문서입니다.
> 결론부터: **작업 성격에 따라 6개 모델을 나눠 씁니다.** 순수 정리 작업은 저가 강모델(Solar·DeepSeek), 창의 작업은 여러 모델 후보 → 사람 선택, 검증은 독립 모델.

## 0. 이번 커밋에 바뀐 것

역할 배분(role map)을 실제 코드로 반영했습니다.

| 파일 | 변경 |
|------|------|
| `server/orchestrator/registry.js` | role map 확정: `report → DeepSeek-V3.2`(Solar에서 교체), `verify`(독립 검증) 신설, `CONCEPT_LENSES`(컨셉 4렌즈=4모델) 추가 |
| `server/orchestrator/adapter.js` | 모델 슬러그 추가(DeepSeek·Kimi·Mistral), `concept`/`verify` 프롬프트·토큰·목업 |
| `server/orchestrator/index.js` | **컨셉 엔진**(`kind:"concepts"` — 렌즈별 다른 모델이 후보 생성, 자동 합치기 없이 배열 반환) + **독립 검증**(`kind:"verify"`) 분기 |
| `server/index.js` · `src/api.js` | `pool`(컨셉용 아이디어 풀)·`content`(검증 대상) 전달, `api.concepts()`·`api.verify()` |

## 0-2. 2026-09-18 재측정 — AI 작업이 15개로 늘어난 뒤 (쉬운 말 정리 · 코드 미반영)

백엔드 핸드오프 문서(`IdeationEngine-개발핸드오프/docs/05-AI-작업-목록.md`)에서 AI가 할 일이 **15개**로 정해졌습니다.
지금까지는 작업 4~5종(키워드·아이스·발산·분석·보고)만 기준으로 모델을 골랐는데, 새로 생긴 작업(인터뷰 꼬리질문·뜻풀이·파트 나누기·후보 추천 등)은
그 표로는 안 맞을 수 있어서 **실제로 모델들을 다시 불러서** 쟀습니다. (OpenRouter 실호출 약 370번, 총비용 0.3달러 미만)

**가장 큰 발견은 모델이 아니었습니다.** 응답을 "JSON 형식으로만 달라"고 **강제하는 설정**을 켜는 것이, 모델을 바꾸는 것보다 효과가 컸습니다.
Solar-Pro4는 이 설정 없이는 화면이 못 읽는 형태(줄글)로 답할 때가 45%나 됐는데, 설정을 켜자 0%가 됐습니다.

그 밖에 알게 된 것:

- **실시간으로 답해야 하는 작업 2개**(인터뷰 꼬리질문 판단, "이게 뭐예요?" 뜻풀이)는 사람이 화면 앞에서 기다리는 유일한 작업입니다.
  지금 표의 Solar-Pro4는 평소엔 빠르지만(0.9초) **스무 번에 한 번쯤 11초**가 걸려서 실시간에는 못 씁니다. 이 둘은 품질보다 **속도**로 골라야 합니다.
- **AI 검증·현실성**에서 걱정했던 "검색 결과에 없는 걸 지어내지 않을까"는, 형식을 강제하고 "검색 결과에 없는 건 쓰지 마라"를 프롬프트에 넣으니 **환각이 0건**이었습니다.
  (단, 이번 검색 결과는 실제 Brave가 아니라 짧게 만든 예시라서, 진짜 검색 결과로는 다시 확인이 필요합니다.)

## 2. 우리가 한 테스트들 (전체 기록, 시간순)

각 테스트는 **여러 모델을 블라인드로 대결**시키고 **AI 심판(여러 개) 또는 객관 지표(Vendi·recall)로 채점**했습니다.

### ① 가벼운 작업 (키워드·아이스) — 어느 저가 모델?
- **테스트:** 여러 소형 모델로 짧은 발산·키워드.
- **결과:** **Gemini-2.5-Flash-Lite**가 한국어 안정·품질·최저가 균형 1위. 추론모델은 짧은 작업엔 오히려 꼴찌(예산을 추론에 소모).
- **결정:** 키워드·아이스 = Flash-Lite.

### ② 무거운 작업: 분석(analyze) — 추론모델이 유리할까?
- **테스트:** 8종(추론4+강범용4)이 같은 아이디어 묶음을 테마화. 심판 3, 블라인드.
- **결과:** **Solar 4.43 (1위) + 최저가.** Kimi 4.3, Grok 4.17, Nemotron 4.07, GLM 3.9, DeepSeek 3.8, Gemini 3.67, Qwen 2.5.
- **교훈:** "추론모델이 무거운 작업 유리" 가설은 **무너짐**(추론모델이 하위권). → 분석 = Solar.

### ③ 보고서(report) — 분석과 같이 취급해도 되나?
- **테스트:** 같은 8종이 더 무거운 "종합·로드맵" 작성. 심판 3.
- **결과:** **DeepSeek 4.57 (1위)**, Solar 4.53(근소 2위·4배 쌈), Kimi 4.5.
- **교훈:** 더 무거운 종합에선 추론형(DeepSeek)이 근소 1위. → **report = DeepSeek** (진짜 다른 모델로 분업).

### ④ 아이디어 생성: 단일 vs 다중 (가장 오래 헤맴 — 결론 두 번 뒤집힘)
- **처음:** 4관점을 여러 모델에 나눠 생성 → 합치기(앙상블)가 더 좋아 보였음.
- **교란 제거:** 그 "승리"는 baseline이 약한 모델이었던 착시. 공정하게 하니 **단일 Solar가 앙상블을 이기고 11~18배 쌌음.** (약한 모델 섞으면 "품질 희석")
- **재대결:** 같은 강모델을 **여러 번**(Self-Refine: 초안→비평→수정)이 단일 1회를 이김(4.53 vs 3.97). "다른 모델 섞기"(이종)는 여전히 짐.
- **다양성 재측정(Vendi):** 단일 Solar **6.06** > 다중 4.90 → **단일이 더 다양**(그냥 섞으면 뻔한 아이디어로 수렴).
- **강제 분산(steelman):** 렌즈를 강제로 벌리면 다중이 단일과 **대등**(5.05≈5.03)까지.
- **결정:** 발산 기본 = **단일 Solar**, 품질옵션 = **Self-Refine**. "자동으로 섞어 더 좋다"는 **반증됨.**

### ⑤ 컨셉 종합: 단일 vs 다중 — 다중이 사는 곳
- **테스트:** 같은 아이디어 풀·4렌즈로 단일(Solar×4렌즈) vs 다중(4모델×4렌즈) 컨셉 생성 → Vendi 다양성.
- **결과:** **다중 2.79 > 단일 2.68** (6골 중 5골 다중 우위). 비용 85배지만 **세션당 1회 4개뿐이라 절대액 무의미**($0.0085).
- **결정:** **컨셉 = 다중(4모델×4렌즈)** — 여기가 "여러 LLM"이 정직하게 값하는 자리.

### ⑥ 검증(verify) — 어느 모델이 결함을 잘 잡나 + 독립성
- **테스트 1:** 오류·환각을 심은 결과물 → 어느 모델이 잘 잡나(recall). **Solar 100%·최저가** 등 상위권 다 98~100%(포화). GLM만 30~64%(빈응답 불안정).
- **테스트 2 (핵심):** Solar가 만든 결과물을 **Solar-self vs Llama/DeepSeek-other**가 검증 → **독립 모델이 자기검증이 놓친 유효 결함을 더 잡음**(Llama 2.0 vs 1.3 / DeepSeek 2.8 vs 2.5).
- **결정:** 검증 = **생성자와 독립 모델(Llama)**. "Solar가 검증도 잘해서"가 아니라 **자기가 만든 걸 자기가 검증하면 맹점을 못 본다**는 방법론.

### ⑦ 상위(플래그십) 모델 대비 — "저렴하지만 좋다" 객관 입증
- **지적:** 지금까지 중·저가끼리만 비교 → 상위 모델 대비 객관성 부족.
- **테스트:** 우리 저가 픽 vs 플래그십 6종(Claude-Opus·GPT-5.6·Gemini-Pro·Grok-4.6·DeepSeek-V4-Pro·Qwen-max)이 분석·보고 대결. 심판 3, 블라인드.
- **결과:**

| 순위 | 모델 | 티어 | 품질 | Solar 대비 비용 |
|---|---|---|---|---|
| 1 | **DeepSeek-V3.2** | **우리** | **4.40** | 4배 |
| 2 | Claude-Opus-4.1 | 최고가 | 4.21 | **671배** |
| 3 | GPT-5.6-terra / Grok-4.6 | 상위 | 4.08 | 505 / 103배 |
| 5 | **Solar-Pro4** | **우리(최저가)** | **4.03** | 1배 |
| 6~8 | DeepSeek-V4-Pro / Gemini-Pro / Qwen-max | 상위 | 3.81 / 3.33 / 2.06 | 55~141배 |

- **교훈:** **우리 저가 픽이 671배 비싼 Claude-Opus를 이기거나 대등.** Gemini-Pro·Qwen-max는 오히려 우리 Solar보다 낮음. → **"저렴하지만 좋다"가 상위 모델 대비 강하게 성립**(정리 작업 한정).

### ⑧ 창의 "사람 눈" 축 (진행 중)
- LLM 심판은 참신함보다 다듬어진 완성도를 좋아함(편향). 그래서 창의는 **사람 블라인드 채점**으로.
- 지금까지: 사람이 다중 후보를 **4:2**로 선호(단, **n=1·약함**). → **창의 사람축 강화는 다음 과제**(발산에서 다중을 쓸지 최종 결정).

## 3. 핵심 패턴 3가지

1. **객관·정리 작업은 저가 강모델(Solar/DeepSeek)이 지배** — 뭘 재도 대부분 Solar가 최고+최저가, 보고만 DeepSeek. 상위 플래그십도 못 이김.
2. **다중 LLM의 정직한 자리는 딱 2곳** — (a) **창의 후보 생성**(여러 모델 후보 → 사람 선택) (b) **검증 독립**(생성≠검증). "같은 작업 자동 섞어 품질 우위"는 반증됨.
3. **난이도 라우팅으로 비용 절감** — 가벼움(Flash-Lite)/무거움(Solar) 2단으로 비용 크게↓. 플래그십 대비 100~671배 쌈.

## 4. 정직한 한계 (과장 금지)

- 대부분 **LLM 심판·객관 지표** 기반. **사람 평가는 n=1(본인)**이라 창의 판정은 잠정.
- 점수가 천장(3.8~4.6)에 몰려 상위 모델 간 차가 작음. 검증은 거의 포화.
- 표본 n=4~10, **한국어 아이디어 발산·정리** 과제에 한정 — 다른 유형(코드·수학 등)엔 다를 수 있음.
- 발산에서 다중을 최종 채택할지는 **창의 사람축 강화 후 확정.**
