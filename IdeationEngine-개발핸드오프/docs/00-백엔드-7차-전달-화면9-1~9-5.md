# 백엔드 7차 전달 — 화면 9-1 ~ 9-5 (파트 나누기 · 겹친 후보 질문 · 배치 초안 · 팀장 확정 · 보고서)

주제가 정해진 뒤(8-7) **누가 무엇을 맡을지 정하고 보고서를 만드는** 범위예요. 화면 폴더: `screens/09-1-part-split`, `screens/09-2-overlap-questions`, `screens/09-3-assign-draft`, `screens/09-4-leader-confirm`, `screens/09-5-report` (각 README에 화면 설명). 9번 공통 동작은 `assets/js/team.js`. 발산(8번)을 아직 안 만들었어도 **테스트용 데이터를 DB에 직접 넣어** 이 범위만 따로 만들 수 있어요(아래 "테스트 준비").

## 정해진 규칙

1. **파트는 세 종류** — 결과를 좌우하는 파트(core) · 보통 파트(normal) · 작은 일(small, 스킬 없이 누구나). 주제 확정 직후 AI 작업 11이 확정 주제 · AI 검증 · **이름 없는** 팀 스킬(P1 · P2…)로 파트와 후보를 만들어요.
2. **후보는 프로필 스킬로** — 한 파트에 후보가 2명 이상이면 "겹침"이라 **그 사람들에게만** 추가 질문 2개(AI 작업 12)를 하고, 1명이면 바로 배정, 없으면 "후보 없음"으로 범위 조정 대안을 제안해요.
3. **추가 질문의 답은 본인과 AI만** 봐요. 결과는 배치표에 "추가 질문으로 정했어요"라고만 나오고 점수 · 비교 근거는 어떤 응답에도 넣지 않아요(AI 작업 13의 근거는 서버에만).
4. **분량 맞추기** — 핵심 파트가 한 사람에게 몰려도 괜찮고, 대신 **작은 일**을 다른 사람에게 더 줘서 네 사람의 분량이 비슷하게(계산이지 AI가 아님). 쏠리면 팀장에게 "옮기기 제안"을 줘요.
5. **팀장** — 주제 확정(8-7 `topic.confirm`) 때 정해지는 참가자 1명(`leaderParticipantId`, 안 보내면 진행자). 배치를 고치고 **확정**하는 사람은 팀장뿐이에요(`팀장만` API를 다른 사람이 부르면 `403 NOT_LEADER`). `session.get`의 `me.isLeader`로 9-3 / 9-4를 가르고요.
6. **단계는 서버가 넘겨요** — `team.split` → (진행자 "추가 질문 시작") `team.questions` → (모두 답하거나 **5분**이 지나면 **서버가 자동**) `team.assign` → (**팀장의 `team.confirm`으로만**) `report`. 겹친 후보가 없으면 `team.questions`를 건너뛰어요. 파트 나누기 AI가 안 끝났는데 넘기면 `409 PARTS_NOT_READY`.
7. **보고서** — 배치를 확정하면 AI 작업 15가 A4 2쪽 내용을 만들어요. **PDF는 서버에서 만들지 않아요**(프론트가 브라우저 인쇄로 저장). **공유 링크도 없어요** — 참가자가 앱에서 보거나 PDF로 나눠요. 확정 뒤 팀장이 담당을 고치면 보고서를 다시 만들고 `report.ready`를 다시 보내요. 세션은 확정 시점에 `status: ended`.

익명 규칙은 [01-백엔드-한눈에-보기.md](01-백엔드-한눈에-보기.md)의 "5. 익명 규칙"(추가 질문의 답 · 점수는 끝까지 비공개, 이야기해 볼 파트 표시는 팀장에게만), AI 작업 11 · 12 · 13 · 15는 [05-AI-작업-목록.md](05-AI-작업-목록.md), 공통 형식은 [02-API-공통-규칙.md](02-API-공통-규칙.md).

## 만들 API (10개)

9-1(parts) → 9-2(questions · answer) → 9-3(assignment · mark) · 9-4 팀장(reassign · suggestion · revert · confirm) → 9-5(report) 순서예요. **이미 있는 API 3개가 바뀌어요**: `topic.confirm`(단계가 `team.split`로 · 요청에 `leaderParticipantId` 선택 · 응답에 `leader`), `session.advance`(9단계 규칙 · `409 PARTS_NOT_READY`), `session.get`(`me.isLeader`). 바뀐 내용은 각 API 상세에 들어 있어요(4차 문서와 겹치는 부분은 이 문서가 우선).

| 메서드 | 경로 | 권한 | 하는 일 | 왜 이번에 필요한가 |
|---|---|---|---|---|
| `GET` | `/sessions/{sessionId}/team/parts` | 세션 참가자 (회원) | 파트와 후보 (9-1) | 9-1 파트 · 후보 목록 (AI 파트 나누기가 끝나야 `ready`) |
| `GET` | `/sessions/{sessionId}/team/questions/me` | 세션 참가자 (회원) | 내 추가 질문 (후보가 겹친 사람만 · 9-2) | 9-2 내 추가 질문 (겹친 후보만) |
| `PUT` | `/sessions/{sessionId}/team/questions/{partId}/answer` | 세션 참가자 (회원) | 추가 질문 답 제출 | 9-2 답 제출 |
| `GET` | `/sessions/{sessionId}/team/assignment` | 세션 참가자 (회원) | 배치 초안 · 분량 (9-3 모두 · 9-4 팀장) | 9-3 · 9-4 배치 초안 · 분량 |
| `PUT` | `/sessions/{sessionId}/team/parts/{partId}/mark` | 세션 참가자 (회원) | 이야기해 볼 파트 표시 · 해제 (9-3) | 9-3 "이야기해 볼 파트" 표시 |
| `PUT` | `/sessions/{sessionId}/team/parts/{partId}/assignee` | 팀장만 (참가자 중 1명) | 맡은 사람 바꾸기 (팀장 · 9-4) | 9-4 담당 바꾸기 (팀장) |
| `POST` | `/sessions/{sessionId}/team/suggestions/{suggestionId}` | 팀장만 (참가자 중 1명) | 옮기기 제안 받기 · 그대로 두기 (팀장) | 9-4 옮기기 제안 받기 / 그대로 두기 (팀장) |
| `POST` | `/sessions/{sessionId}/team/assignment/revert` | 팀장만 (참가자 중 1명) | AI 초안으로 되돌리기 (팀장) | 9-4 AI 초안으로 되돌리기 (팀장) |
| `POST` | `/sessions/{sessionId}/team/assignment/confirm` | 팀장만 (참가자 중 1명) | 배치 확정 → 보고서 만들기 (팀장) | 9-4 확정 → 보고서 (팀장) |
| `GET` | `/sessions/{sessionId}/report` | 세션 참가자 (회원) | 최종 보고서 (9-5 · A4 보고서 보기) | 9-5 A4 2쪽 보고서 · A4 지난 세션 "보고서 보기" |

7차가 맡는 실시간 이벤트는 아래 4개예요. `stage.changed`(2차)로 9-1 → 9-2 → 9-3/9-4 → 9-5가 이동하고, 팀장이면 `team.assign`에서 9-4로 가요(`App.stageScreen`의 세 번째 인자 `isLeader`). 이벤트에도 익명 규칙이 적용돼요 — 답 · 점수 · 누가 표시했는지는 넣지 않아요.

| 이벤트 | data | 받으면 |
|---|---|---|
| `team.parts.ready` | `{"ready":true}` | 파트·후보 목록 불러오기 (AI 파트 나누기 끝) |
| `team.assignment.updated` | `{"version":4}` | 배치 초안 다시 불러오기 (팀장이 바꿈 · 팀원이 표시함) |
| `team.confirmed` | `{"reportReady":false}` | 보고서(9-5)로 이동 |
| `report.ready` | `{"ready":true}` | 보고서 불러와서 A4 2쪽 그리기 |

## 이미 있는 API 중 바뀐 것 3개

| 메서드 | 경로 | 무엇이 바뀌나 |
|---|---|---|
| `POST` | `/sessions/{sessionId}/topic` | 단계가 `team.split`로 바뀜 · 요청에 **팀장(`leaderParticipantId`, 선택)** 추가 · 응답과 `topic.confirmed`에 `leader` |
| `POST` | `/sessions/{sessionId}/stage/next` | 9단계 규칙 추가: `team.split` → `team.questions` → (자동) `team.assign` · `team.assign` → `report`는 팀장의 `team.confirm`으로만 · `409 PARTS_NOT_READY` |
| `GET` | `/sessions/{sessionId}` | `me.isLeader` 추가 (팀장이면 9-4, 아니면 9-3) |

4차 문서의 `topic.confirm` 상세는 이 문서 것으로 갱신됐어요(같은 명세에서 생성).

## 테스트 준비 (발산 단계를 아직 안 만들었어도 되게)

세션 하나를 아래 상태로 만들어 두면 7차만 따로 테스트할 수 있어요.

- 참가자 4명(회원 · 프로필 있음), 진행자 1명 포함
- 프로필 스킬 예: 노형원(프론트엔드 · 발표·피칭 · 서비스 기획) · 이세민(프론트엔드 · 웹 디자인 · 발표·피칭) · 김승희(웹 디자인 · PPT 디자인 · 리서치·사용자 조사) · 박상진(백엔드 · 문서 정리)
- 세션 `status: running`, `stage: team.split`, 확정 아이디어 1개, 팀장 참가자 1명
- 투표 결과 · AI 검증은 보고서에 쓰이니 최소한의 값(1위 3표, 2위 2표, 등급 go)만 넣어두면 돼요

## 확인이 필요한 것

- **팀장을 누가 정하나** — 지금은 주제 확정(8-7) 때 진행자가 그대로 팀장이에요(`leaderParticipantId`는 준비됐지만 8-7에 고르는 UI가 없음). 디자인 필요.

- **API id**: `team.mark` (프론트: `api.call('team.mark', …)`)

}

- 표시하면 team.assignment.updated 이벤트(팀장 화면 갱신).

### `POST /api/v1/sessions/{sessionId}/team/assignment/confirm` — 배치 확정 → 보고서 만들기 (팀장)

- **API id**: `team.confirm` (프론트: `api.call('team.confirm', …)`)
- **누가 부를 수 있나**: 팀장만 (참가자 중 1명)
- **하는 일**: 지금 배치를 확정하고 보고서 단계로 넘긴다. 모두의 화면이 보고서(9-5)로 이동한다.

**요청 본문**

```json
{
  "version": 3
}
```

**응답** `200`

```json

  "reportReady": false,
  "stage": {
    "id": "report",
    "label": "파트 나누기 · 보고서",
    "subStep": 6,
    "progress": 100
  }
}
```

**에러**

| code | HTTP | 언제 |
|---|---|---|
| `NOT_LEADER` | 403 | 팀장이 아님 |
| `VERSION_MISMATCH` | 409 | 보고 있던 배치가 최신이 아님(그 사이 바뀜) → 다시 불러온 뒤 확정 |
| `ASSIGNMENT_CONFIRMED` | 409 | 이미 확정됨 |

**백엔드 메모**

- 요청의 version이 서버 배치 version과 다르면 409 (다른 창에서 바꾼 걸 모르고 확정하는 것 방지).
- 확정하면 team.confirmed + stage.changed(report) 이벤트, AI 작업 15(보고서 요약·워크플로우)를 시작. 끝나면 report.ready.
- 세션을 끝난 상태(status=ended)로 바꾸고 지난 세션 기록(A4)의 reportAvailable=true.

**백엔드 메모**

- AI 작업 15가 끝나기 전에는 {"ready": false} → 끝나면 report.ready 이벤트.
- 세션이 끝난 뒤에도 그 세션 참가자였던 회원은 계속 볼 수 있다(지난 세션 기록 A4의 "보고서 보기").
- 공유 링크는 만들지 않는다(2026-09-18 결정) — 보고서는 참가자가 9-5 · A4에서 보거나 PDF로 저장해서 나눈다. 응답에 shareUrl 없음.
- "PDF로 저장"은 프론트가 브라우저 인쇄(A4)로 만든다 — 서버 PDF 생성은 필요 없음.
- 익명 규칙: 아이디어 주인·파트 담당 이름은 보여주지만 anonymous 목록의 정보(댓글 작성자·투표자·인터뷰 원문·추가 질문 답)는 절대 넣지 않는다.
- 워크플로우의 할 일·넘겨주기는 AI 초안이다. 검색 결과가 근거인 부분(searchUrl)만 링크를 단다.
