# 백엔드 3차 전달 — 화면 7-1 ~ 7-7 (아이스브레이킹 · AI 인터뷰 · 재료)

이번에 만들 범위와 **끝났다고 볼 수 있는 기준**이에요. 화면 폴더: `screens/07-1-icebreak-q1-discomfort` ~ `screens/07-5-icebreak-q5-wrapup` (참가자 인터뷰), `screens/07-6-icebreak-host` (진행자), `screens/07-7-diverge-materials` (발산 첫 화면의 재료). 채팅 공통 코드는 `assets/js/icebreak-chat.js` (각 README에 화면 설명).

## 정해진 규칙

1. **AI와 1:1 인터뷰, 답 원문은 본인만** — 질문 5개는 순서가 고정이에요. 답 원문은 `ice.state`(본인)에만 들어가고, 진행자·팀원이 부르는 어떤 API·이벤트에도 원문·작성자를 넣지 않아요. 재료는 이름 없이 "몇 명이 말했는지"(count)만.
2. **꼬리질문은 질문당 최대 1번** — 답이 짧거나 모호하면 AI(가벼운 모델, AI 작업 1)가 꼬리질문을 1번 해요. 꼬리질문에 또 짧게 답해도 다음 질문으로 넘어가요. `ice.skip`은 지금 질문(꼬리질문 포함)을 건너뛰고 다음 질문을 줘요.
3. **소식 카드는 세션 시작 직후 미리** — `session.start`(2차) 때 AI 작업 2(검색 + 요약)를 뒤에서 시작해 세션 단위로 캐시해요. 준비되면 세션 전원에게 `icebreak.news.ready`를 1번 보내요. 검색이 안 되면 `ice.news`가 `{"ready": true, "cards": [], "fallback": true}` → 질문 2·3은 건너뛰고 질문 1 다음이 질문 4(step 4).
4. **진행자도 참가자와 똑같이 인터뷰해요** — 세션이 시작되면 진행자도 7-1로 가서 질문 5개에 답하고, 끝나면 "진행자 화면으로 →" 링크로 7-6에 가요. 진도 · 재료 · 인원 수(`memberCount`) 모두 진행자를 포함해요.
5. **재료 뽑기(AI 작업 4)는 한 사람이 끝날 때, 묶기(AI 작업 5)는 진행자가 요약(7-6)을 열 때** — 전원이 끝나길 기다리지 않아요(늦은 사람은 아래 이벤트로). 늦게 끝난 사람 재료는 `icebreak.groups.updated`로 알리고 진행자가 "다시 묶기"를 눌러야 반영돼요. 재료는 빼거나 지우지 않아요.
6. **발산 시작 = 인터뷰 마감** — 진행자가 `session.advance`(2차, from: icebreak)로 넘기면 서버는 단계를 `diverge.write`로 저장하고: 아직 안 끝난 인터뷰는 그대로 닫고(그 사람 답까지만 재료로 뽑기), 이후 `ice.send`·`ice.skip`은 `409 STAGE_CLOSED`. 재료 묶음은 그 시점 것으로 확정해 `ice.materials`로 발산에 넘겨요. 아이스브레이킹에서 대기실로 되돌리기는 없어요(`session.back`은 `409 STAGE_LOCKED`).
7. **중복 · 재접속** — `ice.send`의 `clientMessageId`가 같으면 새 메시지를 만들지 않고 이전 응답을 그대로 돌려줘요. 새로고침 · 재접속은 `ice.state`로 대화와 질문 번호를 복구해요(화면이 이 응답으로 대화를 다시 그려요).

단계 순서와 익명 규칙은 [01-백엔드-한눈에-보기.md](01-백엔드-한눈에-보기.md)의 "4. 세션 단계"와 "5. 익명 규칙", AI 작업 1~5번은 [05-AI-작업-목록.md](05-AI-작업-목록.md), 공통 형식은 [02-API-공통-규칙.md](02-API-공통-규칙.md).

## 만들 API (12개)

참가자 화면(7-1~7-5)이 부르는 건 send · skip · news · react · explain · myMaterials, 진행자(7-6)는 overview · regroup · focus, 발산 첫 화면(7-7)은 materials예요. state · progress는 화면이 아직 안 부르지만 새로고침 복구와 "팀 진행" 카드의 첫 그리기에 필요해서 함께 넣었어요. **2차(대기실 · 단계 넘기기 · 실시간)가 끝난 서버** 위에 얹는 범위예요.

| 메서드 | 경로 | 권한 | 하는 일 | 왜 이번에 필요한가 |
|---|---|---|---|---|
| `GET` | `/sessions/{sessionId}/icebreak/me` | 세션 참가자 (회원) | 내 인터뷰 상태 | 7-1~7-5 화면을 열 때 대화 · 질문 번호 복구 (새로고침 · 재접속) |
| `POST` | `/sessions/{sessionId}/icebreak/messages` | 세션 참가자 (회원) | 인터뷰 답 보내기 | 7-1~7-5 보내기 / Enter |
| `POST` | `/sessions/{sessionId}/icebreak/skip` | 세션 참가자 (회원) | 이 질문 넘어가기 | 7-1~7-5 "넘어가기" |
| `GET` | `/sessions/{sessionId}/icebreak/news` | 세션 참가자 (회원) | 최근 소식 카드 3장 | 7-2 소식 카드 3장 (화면이 이 응답으로 카드를 그림) |
| `PUT` | `/sessions/{sessionId}/icebreak/news/{cardId}/reaction` | 세션 참가자 (회원) | 소식 카드 반응 | 7-2 카드 반응 (처음 들어요 · 들어봤어요 · 잘 알아요) |
| `POST` | `/sessions/{sessionId}/icebreak/explain` | 세션 참가자 (회원) | "이게 뭐예요?" 뜻풀이 | 7-2 "이게 뭐예요?" 뜻풀이 |
| `GET` | `/sessions/{sessionId}/icebreak/progress` | 세션 참가자 (회원) | 팀 인터뷰 진행 | 7-1~7-6 "팀 진행" 카드 처음 그리기 (그 뒤는 icebreak.progress 이벤트) |
| `GET` | `/sessions/{sessionId}/icebreak/materials/me` | 세션 참가자 (회원) | 내 답에서 뽑힌 재료 (나만 보임) | 7-5 내 재료 목록 (실서버 모드에서 다시 그림) |
| `GET` | `/sessions/{sessionId}/icebreak/overview` | 세션 진행자만 | 진행자 요약 (진도 · 소식 반응 · 재료 묶음) | 7-6 진행자 화면 전체 (진도 · 소식 반응 · 재료 묶음) |
| `POST` | `/sessions/{sessionId}/icebreak/groups/regroup` | 세션 진행자만 | 재료 다시 묶기 | 7-6 "다시 묶기" |
| `PUT` | `/sessions/{sessionId}/icebreak/groups/{groupId}/focus` | 세션 진행자만 | "먼저 보기" 표시 | 7-6 "먼저 보기" 토글 |
| `GET` | `/sessions/{sessionId}/materials` | 세션 참가자 (회원) | 발산 재료 (모두) | 7-7 발산 재료 패널 (먼저 보기 묶음 · 나머지) |

3차가 맡는 실시간 이벤트는 아래 3개예요. `stage.changed`(2차)는 7-1~7-5가 `diverge.write`를 받으면 8-1로 자동 이동하는 데 써요 (7-6 · 7-7에는 처리가 없어서 새로고침 때 `session.get`으로 이동). 이벤트에도 익명 규칙이 똑같이 적용돼요 — 진도·인원 수만, 답 내용은 넣지 않아요.

| 이벤트 | data | 받으면 |
|---|---|---|
| `icebreak.progress` | `{"nickname":"김승희","step":3,"done":false}` | "팀 진행" 카드에서 닉네임이 같은 줄을 "n / 5" 또는 "완료"로 갱신 (줄은 HTML 예시 이름이라 다른 닉네임이면 갱신 안 됨) |
| `icebreak.news.ready` | `{"ready":true}` | 7-1이면 7-2로 이동 (7-2가 열릴 때 ice.news로 카드를 그림). 7-2~7-5에서 받으면 아무 일도 없음 |
| `icebreak.groups.updated` | `{"newMaterials":2}` | 진행자 7-6에 토스트 "새 재료 N개가 들어왔어요 · 다시 묶기로 반영해요" |

## 완료 기준 — 아래가 모두 통과하면 3차 끝

프론트의 `assets/js/config.js`에서 `useMock: false`, `baseUrl`을 서버 주소로 바꾸고 확인해요. **2차(대기실 · 단계 넘기기 · 실시간)가 끝난 서버** 기준이에요.<br>사람마다 **다른 브라우저 프로필**(또는 다른 브라우저)로 로그인해요 — 같은 프로필의 창끼리는 로그인 정보가 섞여요.<br>화면에 아직 버튼이 없거나 서버 데이터를 아직 그리지 않는 동작은, 그 사람 창의 개발자도구 **콘솔에서 `await api.call(…)`** 로 부르거나 **Network 탭의 응답**으로 확인해요.<br>진행자 1명 + 참가자 2명 이상(4명 권장)으로 방을 만들고 "세션 시작"을 누른 뒤 확인해요. 진행자도 7-1로 가서 인터뷰를 하고, 끝나면 대화창 마지막의 "진행자 화면으로 →" 링크로 7-6에 가요. 인터뷰 시나리오는 진행자 · 참가자 창 모두에서 확인해요.

| # | 시나리오 | 기대 결과 |
|---|---|---|
| 1 | 참가자가 7-1에서 구체적인 답을 보내기 | 다음 질문 말풍선(label "질문 2 · …")이 오고 상단 "2 / 5"와 진행 막대 갱신 · 오른쪽 "오늘 나눌 이야기" 2번이 현재로 |

## 이번 범위의 경계

- 방 만들기 · 대기실 · **세션 시작 · 단계 넘기기 · WebSocket 연결 자체는 2차**예요. 3차는 그 위에서 `icebreak` 단계 안의 일만 다뤄요. 세션 시작 직후 소식 카드 작업을 시작하는 것과, `icebreak`를 떠날 때 인터뷰를 마감하는 것은 3차가 맡아요.
- 재료가 발산에서 어떻게 쓰이는지(8-1 제출 · 익명 순위표)는 **4차**예요. 3차는 `ice.materials`까지.
- 7-7의 입력칸(아이디어 한 줄)은 브라우저에 초안으로만 저장하고 서버로 보내지 않아요 → 4차 `idea.submit`.
- 재료를 쓰는 AI 추천(8-2) · 숨은 공통점(8-6)은 **5차**예요.

## 확인이 필요한 것

자세한 내용과 제안은 `_작업메모/친구-확인요청.md`에 있어요. 이 문서는 제안대로 쓴 상태예요.

1. **[프론트] 7-1은 `icebreak.news.ready`를 받을 때만 7-2로 이동** — 카드가 이미 준비된 뒤 질문 2에 도달한 사람은 7-1에 남은 채 질문 2 문장만 받아요. 서버는 이벤트를 세션 전원에게 1번만 보내면 되고, 그 뒤에 온 사람은 프론트가 `ice.news`의 `ready`로 확인해야 해요(프론트 남은 일).
2. **[명세] `ice.send` · `ice.skip`에 발산 시작 뒤(409 STAGE_CLOSED)와 `ice.skip`의 인터뷰 끝(409 INTERVIEW_DONE)이 없음** — 이 문서는 그렇게 동작한다고 썼어요.
3. **[명세] 검색 실패(fallback) 때 step 번호** — 질문 2·3을 건너뛰면 `step: 4`로 보내는 것으로 썼어요(프론트는 값을 그대로 "n / 5"로 표시).
4. **[명세] 없는 cardId · groupId** — 공통 코드 404 NOT_FOUND, 없는 반응 값은 400 VALIDATION으로 썼어요.
5. **[결정됨 2026-09-18] 진행자도 인터뷰** — 프론트 · 문서에 반영했어요(단계 → 화면 표 · 5 대기실 · 7-5 링크).
6. **[디자인] 7-6 "이전 단계"는 항상 409 STAGE_LOCKED** — 2차 문서에도 적혀 있어요.

**백엔드 메모**

### `POST /api/v1/sessions/{sessionId}/icebreak/messages` — 인터뷰 답 보내기

- **API id**: `ice.send` (프론트: `api.call('ice.send', …)`)
- **누가 부를 수 있나**: 세션 참가자 (회원)
- **하는 일**: 내 답을 받아서 AI가 (1) 답이 짧으면 꼬리질문 1번, (2) 충분하면 다음 질문, (3) 마지막이면 끝 안내와 재료를 돌려준다.

**요청 본문**

```json
{
  "text": "과제 공지 놓친 거",
  "clientMessageId": "c_171234"
}
```

**응답** `200`

```json
{
  "step": 1,
  "done": false,
  "messages": [
    {
      "id": "m4",
      "role": "ai",
      "label": "꼬리질문",
      "style": "fq",
      "text": "어떤 과제였고, 공지가 **어디에** 올라와 있었어요?"
    }
  ]
}
```

**에러**

| code | HTTP | 언제 |
|---|---|---|
| `INTERVIEW_DONE` | 409 | 이미 끝난 인터뷰 |

**백엔드 메모**

- 꼬리질문은 질문당 최대 1번. "짧다/모호하다" 판단은 AI(저가 모델)가 한다.
- 질문 2로 넘어갈 때 news 카드가 준비 안 됐으면 {"role":"ai","style":"wait"} 안내를 먼저 보내고, 준비되면 icebreak.news.ready 이벤트.
- 응답이 느리면 SSE/스트리밍으로 바꿔도 된다(프론트는 messages 배열만 그리면 됨).
- 답 원문은 이 사람 본인에게만 보인다. 진행자·팀원 API 어디에도 원문을 넣지 않는다.

### `PUT /api/v1/sessions/{sessionId}/icebreak/groups/{groupId}/focus` — "먼저 보기" 표시

- **API id**: `ice.focus` (프론트: `api.call('ice.focus', …)`)
- **누가 부를 수 있나**: 세션 진행자만
- **하는 일**: 진행자는 재료를 고르지 않고, 먼저 이야기할 묶음만 표시한다.

**요청 본문**

```json
{
  "focus": true
}
```

**응답** `200`

```json
{
  "groupId": "grp_3",
  "focus": true
}
```
