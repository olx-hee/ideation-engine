# 백엔드 4차 전달 — 화면 8-1 · 8-3 · 8-4 · 8-6 · 8-7 (발산 기본 · AI 없이 끝까지)

이번에 만들 범위와 **끝났다고 볼 수 있는 기준**이에요. 화면 폴더: `screens/08-1-idea-write`, `screens/08-3-idea-board`, `screens/08-4-idea-comments`, `screens/08-6-vote`, `screens/08-6w-vote-wait`(투표 마친 뒤 대기), `screens/08-7-vote-result-host`(진행자 · 참가자 보기 전용) (각 README에 화면 설명). **AI 없이** 아이디어 제출 → 익명 순위표 → 익명 댓글 → 투표 → 결과 · 주제 확정까지 끝까지 돌아가는 게 목표예요. AI 추천(8-2) · AI 검증(8-5) · AI가 모은 아이디어 · 숨은 공통점은 5차예요.

## 정해진 규칙

1. **아이디어 주인은 결과(8-7) 때만, 댓글 작성자·투표자는 끝까지 비공개** — 투표 결과 전에는 `idea.board` · `comment.targets` · `comment.list` · `vote.state` · `vote.candidate` 어디에도 닉네임 · participantId · `source`(AI 추천 여부)를 넣지 않아요. 진행자에게도 마찬가지예요. 응답에서 걸러내는 건 서버 한 곳(직렬화 계층)에서 하고 테스트를 만들어 주세요.
2. **별칭(팀원 A·B·C·D)과 줄 순서는 세션마다 무작위로 한 번 정해 고정** — 제출 순서·입장 순서와 달라야 해요. `isMe`는 요청한 본인 줄에만 true. 댓글 목록도 작성 시각순으로 주지 않아요(시간으로 사람을 추측하지 못하게).
3. **전원이 내야 넘어가요 (제출 강제)** — `diverge.write`는 `memberCount` 전원이 `idea.submit`을 해야, `diverge.comment`는 전원이 아쉬운 점 할당량(`concernDone` = `concernTotal`)을 채워야 `session.advance`가 통과해요. 아니면 `409 NOT_ALL_SUBMITTED`(details에 `pendingCount` · `memberCount`). 연결이 끊긴 사람 때문에 막히면 진행자가 `force: true`로 넘길 수 있고, **그때만** 제출 안 한 사람(빈 줄)이 생겨요.
4. **단계를 떠날 때 마감** — 넘어가면 서버는 단계를 먼저 저장하고 `stage.changed`를 보내요. `diverge.write`를 떠나면 `idea.submit`은 `409 STAGE_CLOSED`, `diverge.comment`를 떠나면 `comment.create`도 `409 STAGE_CLOSED`. `diverge.review`는 4차 서버(AI 없음)에서는 바로 넘어가요 — 5차가 붙으면 검증이 끝나기 전 review → vote는 `409 STAGE_LOCKED`(5차 문서).
5. **투표 → 결과 전환** — `memberCount`(진행자 포함 · 내보낸 사람 제외) 모두가 `vote.finish`를 하면 서버가 자동으로 단계를 `diverge.result`로 **저장한 뒤** `stage.changed` → `vote.closed`를 보내요. 진행자가 `session.advance`(from: diverge.vote)로 넘겨도 같은 처리(안 마친 사람 표는 저장된 대로 집계). 저장이 이벤트보다 먼저여야 해요 — 8-6w(대기)가 `vote.closed`를 받고 8-7을 열 때 `session.get`이 아직 vote면 8-6으로 튕겨요. 투표를 마친 사람은 8-6w에서 기다리고, `vote.closed`가 오면 **모두** 8-7로 가요(참가자는 보기 전용).
6. **결과 → 투표는 `vote.revote`로만, 결과 → 파트 나누기는 `topic.confirm`으로만** — 재투표는 단계를 `diverge.vote`로 되돌려 저장하고 후보를 동점 id로만, `maxVotes`를 1로, 모두의 `finished`를 초기화해요. 주제 확정은 단계를 `team.split`로 저장하고 `topic.confirmed`(팀장 포함) + `stage.changed`를 보내요 → 모두 9-1로. 파트 나누기 AI 작업을 이때 시작해요(7차).
7. **4차 서버는 AI 칸을 비워서 보내요** — `vote.state`의 `candidates[].grade = null` · `aiIdeas = []` · `commonThreads = []`, `vote.candidate`의 `review = null`, `vote.results`의 `ranks[].grade = null` · `aiMerged` 줄 없음 · `insight = null`. `vote.save`는 **지금 `vote.state`에 있는 후보 id만** 받아요(5차에서 AI 아이디어가 후보에 들어오면 자동으로 허용). `idea.submit`의 `source: "ai"` · `recommendationId`는 저장만 하고 검사는 5차에서.
8. **중복 · 되돌리기** — `idea.submit` · `vote.save`는 전체 목록을 덮어쓰는 PUT이라 여러 번 보내도 결과가 같아요. `vote.finish`를 두 번 부르면 두 번째도 같은 200. 진행자가 `session.back`으로 되돌려도 이미 저장된 아이디어·댓글·표는 지우지 않아요.

단계 순서·인원 수 기준은 [01-백엔드-한눈에-보기.md](01-백엔드-한눈에-보기.md)의 "4. 세션 단계", 익명 규칙 표는 같은 문서 "5. 익명 규칙"(⚠️ 4차에서 가장 중요), 공통 형식은 [02-API-공통-규칙.md](02-API-공통-규칙.md), 저장 구조는 [04-데이터-모델.md](04-데이터-모델.md).

## 만들 API (13개)

화면 순서대로 8-1(mine · submit) → 8-3(board) → 8-4(targets · list · create) → 8-6(state · candidate · save · finish) → 8-7(results · revote · confirm)이에요. 8-2 · 8-5와 8-6의 AI 부분(`review.get` · `vote.aiIdea` · `vote.thread`)은 **5차**라 여기 없어요. **2차(대기실 · 단계 넘기기 · 실시간)가 끝난 서버** 위에 얹는 범위이고, 3차(아이스브레이킹) 없이도 테스트할 수 있어요(진행자가 `icebreak`에서 바로 넘기면 됨).

| 메서드 | 경로 | 권한 | 하는 일 | 왜 이번에 필요한가 |
|---|---|---|---|---|
| `GET` | `/sessions/{sessionId}/ideas/me` | 세션 참가자 (회원) | 내 아이디어 1·2·3순위 불러오기 | 8-1 새로고침 · 재접속 때 칸 채우기 (실서버 모드에서 부름) |
| `PUT` | `/sessions/{sessionId}/ideas/me` | 세션 참가자 (회원) | 내 아이디어 제출 | 8-1 "이 순서로 제출" |
| `GET` | `/sessions/{sessionId}/ideas/board` | 세션 참가자 (회원) | 익명 순위표 | 8-3 익명 순위표 (실서버 모드에서 표를 다시 그림) |
| `GET` | `/sessions/{sessionId}/comments/targets` | 세션 참가자 (회원) | 댓글 달 목록 + 내 할당량 | 8-4 왼쪽 목록 + 할당량 (화면이 이 응답으로 그림) |

| `GET` | `/sessions/{sessionId}/vote` | 세션 참가자 (회원) | 투표 화면 목록 + 내 표 | 8-6 후보 · AI 아이디어 · 숨은 공통점 목록 + 내 표 · 8-6w 대기 화면의 `finished` · 인원 |

| `PUT` | `/sessions/{sessionId}/vote/me` | 세션 참가자 (회원) | 내 표 저장 (최대 2표) | 8-6 체크박스 · "이 아이디어에 투표" |
| `POST` | `/sessions/{sessionId}/vote/me/finish` | 세션 참가자 (회원) | 투표 마치기 | 8-6 "투표 마치기" |
| `GET` | `/sessions/{sessionId}/vote/results` | 세션 참가자 (회원) | 투표 결과 + 아이디어 주인 공개 | 8-7 결과 줄 다시 그리기 · 아이디어 주인 공개 (참가자도 같은 화면 · 버튼 숨김) |
| `POST` | `/sessions/{sessionId}/vote/revote` | 세션 진행자만 | 동점만 다시 투표 | 8-7 "동점만 다시 투표" |

4차가 맡는 실시간 이벤트는 아래 5개예요(전부 인원 수 또는 id만 — 누가 냈는지 · 누가 투표했는지는 넣지 않아요). `stage.changed`(2차)로 8-1 → 8-3 → 8-4 → 8-5 → 8-6이 자동 이동하고, 8-6w · 8-7은 `vote.closed` · `stage.changed`(`diverge.result` · 재투표 `diverge.vote`)로 움직여요. 8-6에는 `stage.changed` 처리가 없어서 새로고침 때 `session.get`으로 이동해요.

| 이벤트 | data | 받으면 |
|---|---|---|
| `ideas.submitted` | `{"submittedCount":3,"memberCount":4}` | 8-1 · 8-2에 처리 코드가 아직 없음 → 이벤트 payload로 확인 |
| `comments.progress` | `{"doneCount":2,"memberCount":4}` | 8-4에 처리 코드가 아직 없음 → 이벤트 payload로 확인 |
| `vote.progress` | `{"votedCount":3,"memberCount":4}` | 8-6 아래 "투표한 사람 n / m" · 8-6w "현재 n / m명 투표 완료" 갱신 |
| `vote.closed` | `{}` | 8-6 · 8-6w에 있는 **모두** 8-7로 이동 (참가자는 보기 전용) |
| `topic.confirmed` | `{"ideaId":"ide_c1","title":"…","leader":{"participantId":"par_03","nickname":"김승희"}}` | 진행자는 버튼 응답으로, 참가자는 이 이벤트로 9-1(파트 나누기)로 이동 |

## 완료 기준 — 아래가 모두 통과하면 4차 끝

프론트의 `assets/js/config.js`에서 `useMock: false`, `baseUrl`을 서버 주소로 바꾸고 확인해요. **2차(대기실 · 단계 넘기기 · 실시간)가 끝난 서버** 기준이에요.<br>사람마다 **다른 브라우저 프로필**(또는 다른 브라우저)로 로그인해요 — 같은 프로필의 창끼리는 로그인 정보가 섞여요.<br>화면에 아직 버튼이 없거나 서버 데이터를 아직 그리지 않는 동작은, 그 사람 창의 개발자도구 **콘솔에서 `await api.call(…)`** 로 부르거나 **Network 탭의 응답**으로 확인해요.<br>진행자 1명 + 참가자 3명(4명)으로 세션을 시작하고 진행자 콘솔에서 `await api.call('session.advance', {}, { from: 'icebreak' })`로 `diverge.write`까지 넘긴 뒤 시작해요. 이후 넘기기는 진행자 하단 막대(T2)의 "다음 단계 →"로 해요(콘솔도 됨). 8-4 · 8-6의 왼쪽 목록은 아직 화면 id가 가짜(`ide_0`…)라 **진짜 id는 `idea.board` · `vote.state` 응답에서** 가져와 콘솔로 불러요.

## 이번 범위의 경계

- **5차**: AI 추천(8-2 `idea.recommend`) · AI 검증(8-5 `review.list` · `review.get`) · AI가 모은 아이디어 · 숨은 공통점(8-6 `vote.aiIdea` · `vote.thread` · `vote.threadReact`) · 결과 인사이트 카드. 4차 서버는 이 자리를 `null` · `[]`로 비워서 보내요.
- **8-5 화면은 4차 완료 기준에 없어요** — 목록을 누르면 `review.get`이 없어서 실패해요(토스트 없이 콘솔에만 에러). 진행자가 comment → review → vote로 그냥 넘기면 돼요.
- 주제 확정 뒤(파트 나누기 · 추가 질문 · 배치 · 보고서, 화면 9-1 ~ 9-5)는 **7차**예요. `topic.confirm`의 `leaderParticipantId`(팀장, 선택)와 응답의 `leader`는 7차 문서에 자세히.
- 단계 넘기기 · 되돌리기 · WebSocket 자체는 **2차**예요. 4차는 단계에 들어가고 나갈 때 할 일(전원 제출 확인 · 마감 · 투표 종료 · 재투표 · 확정)만 맡아요. `409 NOT_ALL_SUBMITTED`의 판단(누가 냈는지 세기)은 4차가, 에러를 돌려주는 자리는 2차의 `session.advance`예요.

자세한 내용과 제안은 `_작업메모/친구-확인요청.md`에 있어요. 이 문서는 제안대로 쓴 상태예요.

### `PUT /api/v1/sessions/{sessionId}/ideas/me` — 내 아이디어 제출

- **API id**: `idea.submit` (프론트: `api.call('idea.submit', …)`)
- **누가 부를 수 있나**: 세션 참가자 (회원)
- **하는 일**: 최대 3개를 순위와 함께 제출한다. AI 추천에서 고른 것도 source만 다르고 팀에는 똑같이 "내 아이디어"로 보인다.

**요청 본문**

```json
{
  "ideas": [
    {
      "rank": 1,
      "text": "과제 공지와 마감을 한곳에 모아 알려주는 웹",
      "source": "own"
    },
    {
      "rank": 2,
      "text": "학교 행사·특강 소식 중 관심 있는 것만 골라 알려주는 웹",
      "source": "ai",
      "recommendationId": "rec_1"
    }
  ]
}
```

**응답** `200`

```json
{
  "submitted": true,
  "submittedCount": 3,
  "memberCount": 4
}
```

**에러**

| code | HTTP | 언제 |
|---|---|---|
| `VALIDATION` | 400 | 0개 또는 4개 이상 · 빈 문장 · 순위 중복 |
| `STAGE_CLOSED` | 409 | 이미 다음 단계 |

**백엔드 메모**

- source("own"|"ai")는 서버 내부 통계용. 다른 사람에게 보내는 어떤 응답에도 넣지 않는다.
- 아이디어 주인(participantId)은 저장하되, 투표 결과(8-7) 전까지는 어떤 응답에도 넣지 않는다.
- 제출할 때마다 ideas.submitted 이벤트(인원 수만)를 보낸다.
